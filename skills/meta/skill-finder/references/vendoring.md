# Vendoring into sleeperagentai/skills

## Layout the repo expects

```
skills/<category>/<name>/SKILL.md      name == folder == frontmatter name
skills/<category>/<name>/metadata.json provenance; the skills CLI never installs this file
skills/<category>/<name>/LICENSE       required (copied from the upstream repo root if the skill has none)
categories.json                        allowed categories
catalog.json, README.md                regenerated by scripts/build-catalog.py; CI fails if stale
```

The skills CLI walks `skills/` three levels deep, so `skills/<category>/<name>` is discovered by
`npx skills add sleeperagentai/skills --skill <name>` without any extra flags.

## What `vendor.sh` does

1. Refreshes the cache clone and checks the category and name (collision → exit 1 with a suggested
   `--name <name>-<owner>`; an existing `add/<name>` branch → exit 6 with the PR number).
2. Resolves the upstream commit (default branch HEAD unless `--commit`) and the skill path
   (`**/<name>/SKILL.md`, shortest path wins; root `SKILL.md` for single-skill repos; or `--path`).
3. Downloads the tarball at that commit into `scratch/` (untrusted), copies only the skill folder
   into a worktree at `work/add-<name>/skills/<category>/<name>/`, dropping any upstream
   `metadata.json`.
4. Ensures a license file exists (exit 2 otherwise).
5. Writes `metadata.json` (`added_by: skill-finder`, `quality` from the scorecard).
6. Runs `build-catalog.py` and `validate.sh` in the worktree (exit 4 on failure, worktree kept).
7. Commits with a fixed plain message, pushes `add/<name>`, opens the PR from `templates/pr-body.md`,
   records it in `state/pending.json`, prints `PR=<n> URL=<url> BRANCH=add/<name>`.

`--dry-run` stops after step 6 and prints the diff stat. `--no-pr` pushes without a PR.

## Manual recovery

- Validation failed (exit 4): `cd "$(bash "$SKILL_DIR/scripts/ensure-cache.sh" --print-root)/work/add-<name>"`,
  fix the files, `python3 -I scripts/build-catalog.py`, `bash scripts/validate.sh`, then
  `git add -A && git commit -F ../../state/commit-<name>.txt && git push -u origin add/<name>` and
  `gh pr create --repo sleeperagentai/skills --base main --head add/<name> --fill`.
- Two PRs changed `catalog.json` at the same time: in the worktree,
  `git fetch origin main && git rebase origin/main`, then rerun `build-catalog.py`, `git add -A`,
  `git rebase --continue`, `git push --force-with-lease`.
- Wrong category after merge: move the folder in a new PR and update `metadata.json.category`.
- Remove stale worktrees: `git -C <cache>/repo worktree prune`.

## Name collisions and aliases

Folder names must match the frontmatter `name`. If upstream's frontmatter name differs from the
folder people know (for example `design-taste-frontend` vs "taste-skill"), vendor under the
frontmatter name and put the familiar name in `metadata.json.aliases` so search still finds it.
