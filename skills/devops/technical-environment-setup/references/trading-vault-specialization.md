# Trading Vault Example - Specialized Knowledge Vault

This document shows how the technical-environment-setup skill can be specialized for a specific domain like trading/system development.

## Structure Adaptation
While the base skill recommends a general knowledge vault structure, domains like trading benefit from specialized organization:

```
Trading/ (or Domain-Specific Vault Name)
├── README.md – Vault overview and purpose
├── learning-plan.md – Domain-specific curriculum (see trading example below)
├── daily-log-template.md – Activity tracking template
├── resources.md – Curated domain resources
├── Phase0-Foundations/ – Core prerequisites
├── Phase1-MarketMechanics/ – Domain-specific fundamentals
├── Phase2-Statistics/ – Analytical tools and methods
├── Phase3-Algos/ – Strategy families and implementation
├── Phase4-Risk/ – Risk management and portfolio construction
├── Phase5-Architecture/ – System design and broker basics
├── Phase6-Prototype/ – Development logs and code
├── Phase7-Testing/ – Validation, optimization, and domain specifics
├── CONTENT/ – Reference materials and documents
├── FINANCES/ – Financial tracking and analysis
├── GENERATED/ – Auto-generated reports and data
├── OPERATIONS/ – Operational procedures and checklists
├── PROJECTS/ – Active projects and initiatives
├── QUEUE/ – Backlog and pending items
└── RESEARCH/ – Investigative notes and experiments
```

## Learning Plan Specialization
The learning plan can be adapted to domain-specific goals:

**Example Goal from Trading Vault:**\n"Build a trading broker for local and FX securities"\n- Time Commitment: ~2 hours/day, 5‑6 days/week\n- Duration: ~24‑30 weeks (6‑7 months) to solid prototype\n- Clear deliverables at end of each phase

## Phase Structure Rationale
Specialized vaults often use phase-based learning where:
1. Each phase builds on previous knowledge
2. Phases represent natural learning progression in the domain
3. Deliverables are tangible and demonstrable
4. Timeboxing prevents getting stuck in theory

## Template Adaptation
Base templates from the technical-environment-setup skill can be customized:
- daily-log-template.md → Add domain-specific metrics and observations
- learning-plan.md → Replace generic objectives with domain milestones
- Additional domain-specific templates (e.g., trade-journal-template.md, strategy-backtest-template.md)

## Integration with Development Workflow
For trading/system development vaults:
- Phase6-Prototype/ contains actual code development
- Use standard software development practices within phases
- Link to external repositories where appropriate
- Include both learning artifacts and production code

## Maintenance Practices
- Weekly review of phase progress
- Monthly adjustment of learning plan based on velocity
- Quarterly deep-dive into specific topics
- Annual restructuring if knowledge domains evolve significantly
