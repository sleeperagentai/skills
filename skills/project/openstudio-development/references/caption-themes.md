# Caption themes (packages/compositions/src/primitives/themes)

Every captioned-clip theme is one self-contained TSX module keyed by ID in `themes/registry.ts`, dispatched by `ThemeDispatcher.tsx`. The typography spec lives in Go (`services/db/store/projects_captioned.go` `CaptionThemes`) and is shipped in the render Plan; the gallery preview is a static SVG at `apps/web/public/caption-themes/<id>.svg`. The standing requirement: **the burned-in caption must match the preview SVG in every detail** — the preview is the design of record, not the module.

## Where the design comes from

- Designs arrive as a Claude Design export (`openstudio-designs/*.html`): a `<script type="__bundler/manifest">` with gzip+base64 pages, often NESTED (unpack, find another manifest, unpack again). Extract per-theme rows (num, slug, sample, font, colours, svg) to a scratch `themes.json`.
- Ship the SVG 1:1: convert `sc-camel-<attr>` attributes to camelCase and nothing else; round-trip an already-shipped SVG to confirm byte-identity before writing new ones.

## Module conventions

- Derive every px from the preview: `const k = fontSize / PREVIEW_FONT_PX` (the preview's body font size) and multiply preview px by `k`; em-relative values scale on their own. Put the preview numbers in the module doc comment so the next edit can re-derive them.
- Wrap-first: `flexWrap: 'wrap'` + `whiteSpace: 'normal'` + `columnGap` + `rowGap: Math.round(fontSize * 0.25)` + `overflowWrap: 'break-word'` + `wordBreak: 'break-word'`; `alignItems: 'baseline'` (still well-defined per wrapped line). Captions MUST NOT overflow the frame; wrap onto 2–3 lines before the font shrinks — the planner's word count/wording is sacred, do not re-chunk. `break-word` is non-negotiable on EVERY text container (not just `WordRun`): a single long word (URL, 40-char hashtag) can still exceed one line after the font hits the hard-pixel floor, and without `break-word` CSS lets it escape the frame. The 18 pure-text themes each own their own container `<div>`, so a change to `WordRun` alone does NOT cover them — grep `themes/*.tsx` for `flexWrap` and audit every match. For wide-tracked text (`letterSpacing` 0.3em) set `columnGap: 0` — each word already carries its trailing tracking, so a gap on top doubles the word space and the run comes out ~2× wider than the preview.
- Pass a `maxWidth` to `WordRun` (`videoWidth * 0.9 − padX*2`) so wrapping triggers at the safe-area edge; without it the inline-flex collapses to min-content and never wraps.
- Frame-fit lives in `primitives/caption-frame-fit.ts::fitFontSize({chunkText, baseFontSize, safeWidthPx, activeWordLen, activeScale})` — ONE helper used by `<Captions>`, `<ThemeDispatcher>`, and `<ThemeCaptions>`. Do not re-invent per-dispatcher shrink math; a stale copy fights the shared contract. The overflow guarantee is a STACK of safety nets, applied in order: (1) scale `baseFontSize` by `CAPTION_SIZE_MULTIPLIER` for readability; (2) wrap across `safeWidth × maxLines` (default 3) before shrinking; (3) proportional shrink down to a fractional floor (default 50% of scaled base); (4) if still too wide, keep shrinking to `hardFloorPx` (default 18px); (5) `overflowWrap: 'break-word'` on the run splits glyphs if even 18px isn't enough. Removing any layer re-opens the overflow bug — all three dispatchers depend on the full ladder.
- Ergonomic multipliers (size, line-height, etc.) belong in the shared helper, NOT in the Go theme registry (`services/db/store/projects_captioned.go`). The registry entries are the design of record — the preview SVGs under `apps/web/public/caption-themes/` were authored against those exact numbers. Changing a registry `FontSize` desyncs preview↔render; changing `CAPTION_SIZE_MULTIPLIER` in `caption-frame-fit.ts` keeps them in sync because both the renderer and (future) preview-regenerator read it.
- Measured surfaces (chalk slate, tape, torn paper, sticky note, cardboard, sand, label) MUST derive height from `layout.height` with a `minH` floor at the preview box, not pin to the preview height: `const padY = Math.max(minPad, (minH - runH) / 2); const H = Math.max(minH, runH + padY * 2);`. A hardcoded `80 * k` clips the second wrapped line even after `WordRun` wraps correctly.
- `activeScale > 1` themes (BeastMode 1.25×, Megaphone 1.6×) must pass `activeWordLen` to `fitFontSize` — the per-word bonus bills the shouted word's extra width per-line, scaling the whole-chunk estimate is pessimistic and shrinks fine-sized chunks.
- Read `activeScale`, colours, stroke from `typography`; keep a module fallback only for the preview ratio. In Go set `ActiveScale` to the REAL preview ratio (e.g. 32/28) — a `1.0` is a value, not "unset", so `?? fallback` never fires and the active word silently stops growing.
- Anything that needs word geometry (flash behind the active word, torn-paper circle, tape strip) uses `useRunLayout` from `themes/material.tsx` and MUST await `themeFontsReady` (`themes/fonts.ts`) before trusting the boxes: `document.fonts.check()` is true for a family that has not been registered yet, so early measurement returns fallback-font metrics (~15% narrower) and the plate ends up short.
- Anisotropic (motion-blur) ghost on HTML text: CSS `filter: blur()` is isotropic and SVG `feGaussianBlur "3 0.5"` via `filter: url(#id)` is unreliable on HTML text in headless Chrome — squash the copy with `scaleX(1/n)`, blur, then stretch the wrapper `scaleX(n)`.
- Word-timed effects (karaoke wipe, typewriter cursor) use `useCurrentFrame()/fps` against the word's own `startMs/endMs`, not chunk `progress`; previews freeze these at 60% of the word.
- `@remotion/google-fonts` registers some faces under a spelled-out family (`VT323` → `"VTThreeTwoThree"`); a CSS stack that only names the Google name falls through to the system fallback with no error. Check the loader's `meta.fontFamily` for any digit-named font and lead the stack with that name (Go spec + `fonts.ts`).
- Remove the old renderer path entirely when replacing a theme family (no `PlateID`-style side channel): one module per ID keeps Go↔TS a single contract. `grep -rn` the old key across `.go/.ts/.tsx/.yaml/.md` before declaring it gone.

## Verify by rendering — code review alone misses the real bugs

1. Dump the Go spec as JSON with a throwaway `main` that encodes `store.CaptionThemes` (run inside `services/db` — `go.work` means `go build ./...` at repo root fails; build per module).
2. Render one still per theme with `@remotion/bundler` + `@remotion/renderer.renderStill` (`chromiumOptions: { gl: 'angle' }`), inputProps `{ Composition: 'CaptionedClip', Width: 1080, Height: 1920, Fps: 30, Plan }` where Plan = `{ look, scenes:[{position:'middle'…}], words, chunks, themeId, typography }` built from the preview's sample phrase; pick the frame at **60% through the last word** (what every preview shows). Batch ~5 themes per process — bundling once then rendering 18 in a row trips the Google-font fetch timeouts.
3. Rasterise each preview SVG with headless Chrome at scale `fontSize / previewFontPx`, crop the still to its non-black bbox, stack reference over render in one PNG, and LOOK at it (vision). Measure with PIL/numpy where it matters: colour-mask bbox width of the run vs the reference (e.g. tracked text 378 vs 379 px) catches gap/tracking drift the eye rounds off.
4. Finish with a contact sheet of all themes (reference-over-render tiles) and hand the path to the user; strip any debug overlays (measured-box rects, `console.log('[measure]')`) and the `*.tmp.mjs` harness before reporting.

Typical findings this flow surfaces: phantom `letterSpacing` / font stacks that drifted from the design, active state missing entirely, shadows/strokes added that the preview does not have, plates drawn where the preview has none.
