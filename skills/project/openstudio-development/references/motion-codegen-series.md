## What the series is

- Keeps the engine pipeline (transcript word clock → storyboard → design → manifest → one Remotion render); replaces the kit `scenes` stage with **concept (Opus) → assets → scene-code (Sonnet, one sandboxed TSX scene module per beat, N bespoke components, no cap) → engineSceneCheck (gate, tsc, bundle, stills, DOM audit) → vision critique, ≤3 rounds**.
- Deletes: element kit, `limits.json` + budget tables + audit tooling, `services/motion/scenes`, the whole `director` Agent-SDK provider. `engine` becomes the `motion-graphics` default in the same commit (O5). `tsx` provider goes in Phase 4.
- Assets are v1 (D9): Recraft vectors (`aigw.VectorGen`), Higgsfield rasters/clips, offline Lottie library, cast presenter sprites; d3-geo maps — **no `@remotion/maptiler`** (key + network). Rive, Skia and `@remotion/transitions` are dropped from v1 with the evidence recorded in plan §2.3 (`@remotion/transitions` 4.0.533 imports a React-19-only internal; the engine is React 18): their enum values stay in `scene.schema.json`, but the concept prompt/validator, the codegen allowlist (`concept.IsDropped`) and the gate's `SCENE_IMPORTS` must all exclude them — a capability dropped in one layer and still offered in another sends every such beat to the fallback.
- User decisions are in plan §0 (D1–D9, O1–O5). Do not reopen them; add new ones there.

## Lessons from running it

- **A "write the step-level expansion" subagent truncates on this repo** (50 calls spent on recon, zero lines written). Instead: do recon in the parent, fold verified `path:line` anchors into the plan table itself, and write per-task briefs to `~/.hermes/cache/scratch/motion-codegen/brief-t<N>.md` with a "do not re-explore" clause. Briefs with pre-loaded facts finish in 17–30 calls.
- **Three parallel tracks on disjoint trees work** (`services/motion/llm`, `services/ai-gateway/<vendor>`, `services/pricing`+`apps/api` quote calls) while the schema spine (`schemas/motion`, `services/motion/spec`, `cmd/schemagen`) runs. Every brief must list the sibling trees as never-touch/never-stage/never-stash; verify in the parent with `git show --stat HEAD` that only owned files landed.
- **Split 1.3 into 1.3a (schema + generator + spec + fixtures + parity, no commit) and 1.3b (consumer fixes + the one commit)**: the Go consumers (`scenes`, `motionengine/build.go`, `cmd/fixture-manifest`, `apps/worker-core`) all break on regeneration and are a second agent's worth of work.
- **Same a/b split for 1.6**: deps + alias + harness + 12 fixture scenes + an offline chrome test is a 15-item brief and truncates with zero fixtures. Part a = deps + alias + smoke harness + ONE fixture proven offline, finished and committed from the parent; part b = the remaining fixtures as a pure scene-writing brief that names the committed fixture as the reference file.
- **Cadence the user wants: implementation over fixtures, three Sonnet-pinned children wide.** Prove each capability once offline, commit, move to stages/orchestration/worker wiring; do not polish fixture sets. Dispatch 3 children on disjoint Go packages or TS trees with `model: "claude-sonnet-4-5"`, `provider: "anthropic"` (the parent's Opus-class bucket stays free).
- **Review round (task 1.31 shape)**: three read-only reviewers by layer (Go stages/schema, Node gate/check/bundle, Temporal workflow/worker-core), each told to try to defeat the checks; ledger at `docs/plans/<plan>-p1-review.md`; fix tracks by ownership (`services/motion/**`, `services/visuals/tsx + packages/motion-engine/src/node + motion-renderer`, `apps/worker-core + apps/api`). Rules from that round: a Temporal activity that runs a long LLM call wraps it in `heartbeatEvery`, never a single heartbeat before the call; never derive a build/regen id from a COUNT of existing objects (a failed run leaves a gap → collision) — use `max(k)+1` plus `PutIfAbsent`; a `MOTION_*_MAX_USD` of 0 or less means default, never "no cap".
- **The AST gate is not the network boundary; the browser is.** Gate-level URL scans are bypassable (strings assembled at runtime, CSS `url()`, `window.parent`/`Function('return this')` escapes, spread attributes), so offline must be enforced at the Chrome layer (host-resolver rules / CDP request interception on every attached session) with any non-localhost request surfaced as a per-scene issue; gate rules are defence in depth. Prove isolation with an adversarial scene, never only with a cooperative fixture.
- `services/ai-gateway` has 4 pre-existing non-gofmt-clean files (`anthropictext/temperature*.go`, `elevenlabstts/voice_design_test.go`, `higgsfield/higgsfield.go`) — tell implementers not to "fix" them.
- `packages/motion-engine` tests are `node:test` via `tsx --test test/*.spec.ts`, not vitest. LLM recording is env-driven (`MOTION_LLM_RECORD=1`, `MOTION_LLM=recorded`), no `-record` flag; `recordingKeyVersion` is now 4 (image shas + the per-request model in the key). Stages pick their model with `llm.StructuredRequest.Model` — Opus for design-author/brief/concept, Sonnet for scene-code/critique; the provider's default model is only a fallback, so never wire a new stage without setting it. `claude-opus-4-5` is already priced in `llm/anthropic.go` — never add a guessed model id.
- Recraft API (verified 2026-10-20): `POST /v1/images/generations/{vector,raster}`, bearer auth, `model: recraftv4_1_vector|recraftv4_1`, `style_id` XOR style references, `response_format: url`, response `{credits, data:[{url,image_id}]}`.

## Per-task loop (what finished tasks 1.1–1.5, 1.9, 1.10, 1.23, 1.24, 1.27)

1. Recon in the parent (3–5 batched `sed -n`/`grep` calls): every symbol, path and line the task touches, the test runner, the generated types' real field names. Note where the plan row is wrong (e.g. skills live under `.claude/skills`, not `.agents/skills`; the fixture has 11 beats, not 12) and say so in the brief — the plan is not ground truth, the tree is.
2. Brief file `brief-t<N>.md`: verified facts → deliverable → one-command verify block → commit rules (explicit-path staging, `-F` message file, subject from the plan table) → do-not-touch list of concurrently owned trees.
3. Dispatch; the child commits. Deletions first in the parent (destructive guard) — see delegate-task-tool.
4. Parent verify after every return: `git show --stat <sha> | grep '|' | grep -v '<owned paths>'` must print nothing; re-run the verify block; `git status --short | wc -l` is 0 between tasks.
5. Read `deviations` as a review. Design-rule breaches get a `fix(motion): …` commit from the parent before the next dependent task (a knowledge pack or doc that grants itself an exception becomes the next child's ground truth).

### Repo facts the briefs needed

- Schema dialect (`schemas/motion/src`, `load.go`/README) forbids optional properties and inline objects and has no `uniqueItems`: optionals are **required nullables** (`oneOf [X, null]`), arrays are required (may be empty, never `null` — the TS validator rejects null arrays), every nested object is a named def, and uniqueness rules live in `spec.CheckManifest` with a table test.
- `schemagen` is the single generator for Go (`spec_gen.go`), Zod (`packages/motion-engine/src/spec/generated/*`) and the LLM projections (`schemas/motion/gen/llm/*.json` + `services/motion/spec/embed/llm/*`); run `scripts/motion/schemagen.sh -check`, `scripts/motion/make-fixture-manifests.sh -check` and `scripts/motion/make-parity-corpus.py -check` after any schema change. The per-aspect canvas is a constant map in `services/motion/spec/check.go` mirrored by `FRAMES` in `packages/motion-engine/src/layout.ts`.
- `SceneModule.attempts` has `minimum 1`; a host fallback module uses `attempts: 1, fallback: true`.
- Large display text (≥ ~162 px) renders non-byte-identical PNGs under the render Chrome's software GL (Skia draws glyphs as paths past kMaxDFFontSize); host text caps at `MAX_TEXT_PX = 160` and animates with whole-pixel offsets + colour alpha, not `transform`/`opacity`, to keep `determinism.spec` green.
- Scenes never `fetch`, not even a bundle-local path: the host loads Lottie JSON and passes it as `props.assets[id].data`. The gate rejects every `fetch` reference; do not carve exceptions into packs or the contract.
- Knowledge packs (`services/motion/codegen/knowledge`): upstream Remotion text is spliced verbatim by `scripts/motion/sync-knowledge.sh` (frontmatter `sourceSha256` = sha of the vendored skill file); only the `## In this sandbox` section is ours. The vendored skills under `apps/worker-render/motion-renderer/.claude/skills` disappear with the director provider, so the packs embed their own copy of the body. When auditing a pack for forbidden tokens (`fetch`, `delayRender`, URLs), grep only below `## In this sandbox` — the verbatim upstream body legitimately shows those patterns and must not be edited (the sync `-check` would flag it as drift). A `<!-- DROPPED IN V1 … -->` banner on a synced pack therefore goes directly UNDER the `## In this sandbox` marker (above it is upstream body); `source: ours` packs (skia, rive) may carry it at the top. When dropping a capability, also grep the OTHER packs' delta sections for its package name — selectable packs cite siblings (`light-leaks` showed a `TransitionSeries` recipe).
- Capability packages: most of §2.3's deps (`@remotion/{lottie,rive,skia,three,shapes,paths,noise,transitions,effects,motion-blur,light-leaks,media-utils}`, `three`, `@react-three/fiber`, `d3-geo`, `topojson-client`, `@shopify/react-native-skia`, `canvaskit-wasm`, `@rive-app/canvas-advanced`) are already in the pnpm store via `apps/worker-render/motion-renderer`; check with `ls node_modules/.pnpm | grep <pkg>` before telling a child an install needs network (only `world-atlas` and the `@types/*` were missing).
- Offline WASM — the rule for any CDN-loading upstream component: wrap the underlying package host-side, or drop the capability and record the evidence in the plan; never open the network. Outcomes: `@remotion/rive` hardcodes `locateFile → https://unpkg.com/@rive-app/canvas-advanced@<ver>/rive.wasm` with no override prop, AND no `.riv` file exists on this machine or in the pnpm store (`find node_modules/.pnpm -name '*.riv'`), so there is nothing to build a fixture or library from → dropped. `@shopify/react-native-skia` 2.x peers React 19; 1.x binds `Skia = JsiSkApi(global.CanvasKit)` at module-evaluation time (every bundle entry would preload ~7 MB of CanvasKit before `registerRoot`) and its `<Canvas>` paints asynchronously (ResizeObserver → setTimeout → rAF), so `renderStill` output is not byte-stable without a custom `MakeSWCanvasSurface` software-raster helper → dropped. `@remotion/skia`'s `enableSkia(webpackConfig)` is harmless but unused.
- The TSX gate (`services/visuals/tsx/astcheck`) is shared with the legacy `tsx` visual provider (plan O4): scene-only rules (pinned import allowlist, bare-JSX-text outside `<Text>`, `staticFile`/`delayRender`/`Date`/`Math.random`/timers forbidden, member-only resource attrs, CSS transition/animation, size cap) live behind `--profile=scene` / `Checker{Profile: ProfileScene}`; legacy verdicts must stay byte-identical and the existing astcheck tests are the proof. Golden cases in `testdata/scene-cases.json` are the single source of truth for both the Go table test and the later TS wrapper. Gate-check a scene file with `node services/visuals/tsx/astcheck/sidecar/tsx-check.mjs --profile=scene < <file>` (prints `OK` or `REJECT <rule> <msg> (line L:C)`).
- Capability smoke harness (`packages/motion-engine`): fixture scenes live INSIDE the package at `fixtures/scenes/<capability>.tsx`, not under the repo-root `fixtures/motion/`, because tsc and webpack resolve bare imports through the package's own `node_modules` (a tsconfig `paths: {"*": …}` workaround breaks `@types/*` resolution). `@openstudio/motion-engine/scene` has no self-link in `node_modules`, so `webpackOverride` aliases it to `src/scene/index.ts` and tsconfig `paths` mirrors that. `installedVersion()` resolves the package dir and reads `package.json` from it — `three`'s exports map hides `./package.json`, so `require.resolve('<pkg>/package.json')` throws. `src/SmokeComposition.tsx` (`CapabilitySmoke`, `SMOKE_SCENES`) mounts one fixture through `SceneHost` on beat b01 with the deterministic assets from `scripts/make-fixture-assets.ts` (`fixtures/motion/assets`: svg / png + cutout / 2 s ffmpeg `testsrc` mp4 / lottie / presenter pair — byte-identical across runs); `test/capabilities.chrome.spec.ts` stages them into the gitignored `public/{assets,presenter}`, hooks `browser.connection.on('sessionattached', s => s.on('Network.requestWillBeSent', …))` (the renderer already sends `Network.enable` per page), and asserts zero non-localhost URLs plus byte-identical double renders. React 18 peers pin `@react-three/fiber` to exactly 8.18.0 — a looser range resolves a React-19 build that exports `__CLIENT_INTERNALS` and crashes the chrome spec.
- When deleting or adding a worker activity module, update the `Worker module graph loads under node --import tsx` step in `.github/workflows/ci.yml` (it lists `activities/*` by name) and remember `docker/motion-renderer.Dockerfile` runs `node --import tsx src/worker.ts` — there is no `dist/` build for the worker.
- Never run biome's formatter over gate goldens: `services/visuals/tsx/astcheck/testdata/*.tsx` must stay byte-identical to the `source` strings in `scene-cases.json` (the Go table test compares them exactly), so a `biome check --write` there turns a cosmetic reflow into a red test. `biome.json` ignores that directory and `.worktrees/` for this reason; when `pnpm exec biome check .` lists files, restrict any `--write` to the ones you authored and rerun the gate tests before committing the format commit.
- Never name a host-helper prop `role`: biome's `useValidAriaRole` reads `<Text role="display">` as an invalid ARIA role and would flag every generated scene. The type-scale prop is `face` (`display|body|mono`); knowledge packs and tests use `face`.
- Kanban workers run in `.worktrees/t_*` worktrees of this repo and can stage files (e.g. `docs/features/*`) into the main checkout's index mid-task; `git diff --cached --stat` before every parent commit and list their paths as foreign in every brief (shared-checkout rules in delegate-task-tool).
