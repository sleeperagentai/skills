# motion-renderer (apps/worker-render/motion-renderer)

`apps/worker-render/` is a GROUP folder, one package per renderer type (workspace glob `apps/worker-render/*`). The Remotion Temporal worker is `@openstudio/motion-renderer`.

## Remotion packages

- Every published `@remotion/*` (69) + `remotion` is installed, pinned to ONE exact version (4.0.533 at time of writing). Bump all together; mixed versions break the bundler. Source the list from remotion.dev/docs/api + GitHub `packages/` dir, prune via `pnpm install` feedback (npm CLI queries are approval-gated).
- Not on npm despite being in the monorepo: agent-plugin, browser-studio, canvas, compositor, player-a11y, remotion-media, skills, test-utils.
- `@remotion/transitions` >= 4.0.531: `dist/esm/index.mjs` inlines react-dom@19 -> webpack fails under React 18 (`__CLIENT_INTERNALS_DO_NOT_USE...` not found in 'react'). `src/sidecar/renderClaudeTSX.mjs` aliases the bare specifier to the CJS build, gated on detecting the marker. Subpath imports (`@remotion/transitions/fade`) are fine.
- pnpm `ERR_PNPM_IGNORED_BUILDS`: add the package under `allowBuilds:` in `pnpm-workspace.yaml`. pnpm auto-inserts a placeholder line `set this to true or false` — replace it, don't add a second key.
- **Any `packages/compositions/src/**` change requires killing + webpack-cache-clearing + relaunching the renderer, not just a save.** `tsx watch src/worker.ts` only watches motion-renderer's own `src/`, so a sibling workspace package (`@openstudio/compositions`) stays bundled from the webpack persistent cache under `packages/compositions/node_modules/.cache/webpack`. The live worker holds the previous bundle in memory; subsequent renders upload MP4s that look correct from logs but ran the stale TSX. Recipe after merging a compositions PR on main: `kill -TERM <motion-renderer pid> && pkill -TERM -P <pid>`, `rm -rf packages/compositions/node_modules/.cache/webpack`, then relaunch `pnpm dev` in `apps/worker-render/motion-renderer`. Health probe `/healthz` on :4101 confirms the fresh process; the next render log line `bundling compositions` confirms the cache was indeed empty.
- **Bumping any `@remotion/*` version invalidates two caches AND a live module graph; purge all three or renders fail with `Module not found` on the OLD pnpm-hashed path.** pnpm rewrites the virtual-store directory name on every version change (`@remotion+bundler@4.0.528_...` -> `@remotion+bundler@4.0.533_...`), and webpack's persistent cache under `packages/compositions/node_modules/.cache/webpack` records absolute loader paths including that hash. The stale path survives `pnpm install` and keeps resolving `.../4.0.528/.../esbuild-loader/index.js` until (a) `packages/compositions/node_modules/.cache` AND `apps/worker-render/motion-renderer/node_modules/{.cache,.remotion}` are deleted AND (b) the `tsx watch src/worker.ts` process is restarted — a running renderer holds the resolved module graph in memory, so clearing the on-disk cache alone fixes nothing until the next cold boot. Recipe after any `@remotion/*` bump: `pkill -f 'motion-renderer|tsx.*worker.ts'`, `rm -rf packages/compositions/node_modules/.cache apps/worker-render/motion-renderer/node_modules/.cache apps/worker-render/motion-renderer/node_modules/.remotion`, then relaunch `pnpm dev`. Same shape bites any workspace package that depends on a pinned `@remotion/*`.

## Temporal namespace drift (Go vs Node)

Local Temporal dev server uses namespace `default`. Go workers read `TEMPORAL_NAMESPACE` from `.env`; `worker.ts` defaults to the literal `'openstudio'` if `.env` is not loaded first. Wrong namespace = no error, worker sits `RUNNING` forever, workflow stalls at stage `render` ~0.888 then falls back to `RenderInlineActivity`. Verify both workers log the same namespace at boot; keep `TEMPORAL_NAMESPACE=default` in `.env`.

## Director sidecar (`src/director/`, activity `directVideo`)

Remotion documents TWO AI approaches and says which to use: the **Agent Skills workflow** (coding agent inside a real project, `npx remotion skills add`, prompt `/remotion-create <brief>`, Studio/stills to check — "to prompt videos for yourself") and the **Prompt-to-Motion-Graphics SaaS template** (LLM → one component string → sanitize → JIT compile → Player, retry on compile error — "no OS or filesystem access"). The Director is our skills-workflow tier (we CAN give the agent a filesystem, so keep it on that path); `services/visuals/tsx` is the SaaS-template tier. Do not drift the Director toward single-shot generation to save cost — the skills loop is where quality comes from; cost lands at the top of the normal band (~USD 0.75) because of 2–3 Skill-load turns.

A Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`, TS, in-process, `ANTHROPIC_API_KEY`) coding agent that writes `src/Video.tsx` inside a scratch Remotion project (`workspace.ts`), reviews its own stills (`render.ts`: bundle once, `renderStill` for critique, `renderMedia` for the final cut), then uploads via `@openstudio/storage`. Go keeps narration turns for TTS/Whisper; the director concatenates per-turn audio with ffmpeg and offsets Whisper word timings to ONE absolute timeline (`absoluteWords`). `Root.tsx` (dims/fps/duration) is locked to the narration.

## Prompt-driven director variant (`directVideoFromPrompt`)

Sibling activity to `directVideo`, same agent loop and sandbox, different input shape: `{Prompt, Width, Height, Fps, DurationMs}` — no narration audio, no Whisper word timings, no per-turn visualHint. `prepareWorkspaceFromPrompt` writes `brief.md` with the prompt verbatim under `## Prompt`, locks `Root.tsx` to the caller-supplied duration, and seeds a SILENT starter `Video.tsx` with no `<Audio>` element. The provider name `director-prompt` is registered in `services/visuals/routing.go` `KnownProviders`.

- **Add a sibling activity when a renderer kind grows a second input shape; do NOT make the existing activity switchable.** The narration director validates `Turns != []` up front and the SDK gate / brief / Root.tsx are shaped around narration audio + absolute word timings. Making the single activity accept both via optional fields pushes the branch into the agent loop and the Go worker-core workflow (which runs TTS + Whisper BEFORE dispatching) — a prompt-only request on that workflow still pays for TTS it never uses. One activity per input shape, dispatched by distinct `VisualProvider` values, keeps billing and the gate honest.
- **Do NOT flip `KindProviders["motion-graphics"]` to a provider whose activity rejects the current input shape.** `GenerateVideoWorkflow` hydrates `MotionGraphics.Turns` via TTS + Whisper and hands that to whatever provider resolves — a provider whose activity validates `Prompt != ""` and ignores Turns will 500 every production motion-graphics request the instant the default flips. Default-flips are safe only when the new provider accepts a strict superset of the old provider's input. Expose a prompt-driven variant through a dedicated API route + workflow instead.
- **Expanding the sandbox? Three places have to agree or the SDK silently drops a tool.** (a) `checkInit`'s `forbidden` list in `director.ts` — remove the tool from the forbidden set. (b) The query's `tools: [...]` and `allowedTools: [...]` arrays — closed built-in set + MCP tool allowlist; a tool listed in `allowedTools` but not `tools` is NEVER exposed. (c) `makeGate` — add an `allow` branch for the tool, and the matching `director.spec.ts` case (flip the `deny` to `allow`). The SDK built-in `Bash` stays denied; our sandboxed `mcp__director__bash` is a separate MCP tool.
- **Bash sandbox pattern (`src/director/bash.ts`): `sandbox-exec -p '<profile>' /bin/bash -lc <cmd>` on darwin, `unshare -rn /bin/bash -lc <cmd>` on linux, `isError` with a clear message on other OSes.** Profile `(version 1)(allow default)(deny network*)` denies all network; cwd pinned to the scratch project; env scrubbed to `PATH / HOME / LANG`; per-call `SIGKILL` after `cfg.bashTimeoutMs`; stdout+stderr merged and capped at 8 KB. Verify network denial end-to-end with `exec 3<>/dev/tcp/1.1.1.1/80 && echo CONNECTED || echo BLOCKED` — a `CONNECTED` result means the profile is wrong. `sandbox-exec` is Apple-deprecated but functional through macOS 26; the system prompt tells the agent to degrade gracefully if the tool errors.
- **`sandbox-exec` profile text is ONE argv element.** The profile is the single string after `-p`, so unit-testing it with `argv.includes('(deny network*)')` fails — use `argv.join(' ').includes(...)` or inspect the index after `-p`.
- **Live script for the prompt-driven path:** `scripts/director-prompt-live.ts` runs `directVideoFromPrompt` end-to-end through `MockActivityEnvironment` against real MinIO; `DIRECTOR_PROMPT_OVERRIDE="..."` / `DIRECTOR_PROMPT_DURATION_MS=20000` for custom runs. Spends up to `DIRECTOR_MAX_USD` of real credit — same acceptance pattern as `director-live.ts`.
- **Defer the Go workflow dispatch + API route to a follow-up PR when the pricing surface is not figured out.** `services/pricing.augmentLines` and the API's credit-reservation path are the two blockers; shipping `/v1/videos:fromPrompt` without them puts renders in flight that never bill. Register the provider name in `KnownProviders` and ship the live script first — the activity is independently exercisable via `MockActivityEnvironment`, so the plumbing is proven before the billing seam lands.
- **"Prompt-driven" in a renderer that already consumes narration = the SCRIPT is the prompt — do not build a second text field.** When the user asks for a "prompt-driven" director on a narration pipeline, the words the narrator speaks ARE the creative brief; the director reads `brief.md` (containing the script + absolute word timings) and designs visuals that match. Before writing code, state the architecture back in one sentence ("the script you write + the narration audio is what the agent reads; there's no second text box") and get confirmation. Building a separate `visualPrompt` schema field, API wiring, worker-core splat, AND a silent `directVideoFromPrompt` sibling path on an unclarified reading wastes two full implementation cycles — one for each wrong-architecture branch — before the one-line fix (`KindProviders["motion-graphics"] = "director"`) surfaces. Ask explicitly: (a) does narration survive? (b) is this a new activity or does the existing one change? (c) if there's a prompt separate from the script, what does it add that the script doesn't already say?
- **Before wiring a new creative-direction field end-to-end on an MG renderer, grep the wizard for the existing sibling fields.** A new `musicBedSlug` / `visualPrompt` / `brandOverlay` / etc. field goes through API DTO → project settings → `mgRenderPayload` → worker-core → renderer → composition in six touched files, every one of which looks reasonable in isolation. The gate is the wizard: `grep -rn '<existingSiblingField>' apps/web/app/\(app\)/create/motion-graphics/` — if the wizard does NOT send a sibling creative-direction field today, your new field won't be sent either, and shipping the whole six-layer slice ships dead weight until a follow-up wires the UI. Scope the PR to backend + renderer + OpenAPI + seed infra (that part is reusable immediately), register the field in the request DTO as optional, and defer the wizard dropdown to its own small PR that adds the first MG creative-direction surface. State this scope decision explicitly in the PR body so the deferral is obvious. See also `references/static-asset-catalogue.md` for the seven pieces every static-pick field moves through.
- **A separate `visualPrompt` field on a narration director is dead weight — the DirectorTurn already carries `text` (the words being spoken) and the brief already carries the full script.** The 2026-10-17 branch landed a `visualPrompt` field through packages/schemas → apps/api/motion_graphics.go → apps/api/motion_graphics_render.go → apps/worker-core (MGPayload.VisualPrompt + splat onto every turn's VisualHint + directorBrief primary-direction header). The create wizard was never wired to collect it, the user then confirmed the script IS the brief, and the field was left in-place as unused optional fallback (the storyboard-hint path still runs when it is empty/whitespace, which is every call). If a future feature really needs supplementary style direction on top of narration, treat it as a NEW thing to spec with the user — do not resurrect this field without that conversation.
- **Default motion-graphics provider is `director` (narration-driven agent loop), not `tsx` (one-shot).** `services/visuals/routing.go` `KindProviders["motion-graphics"] = "director"`. The pricing line already exists (`services/pricing.augmentLines["director"]`, 2× augment credits/sec), so flipping the default did not 400 any augmented request. Narration pipeline unchanged: TTS + Whisper still hydrate `MotionGraphics.Turns` before `runDirector` dispatches `directVideo`; the agent sees the stitched narration + absolute word timings and the script via brief.md.

## worker.ts gotchas

- Repo-root `.env` is resolved relative to the file (4 levels up), NOT cwd; a cwd-relative path silently loads 0 vars after a move. `pnpm dev` prints `injected env (N)` — N=0 means wrong path.
- SIGTERM handler is idempotent; `tsx watch` sends it twice and a second `worker.shutdown()` throws `IllegalStateError: Not running. Current state: STOPPED`.
- **`Worker.shutdown()` returns void.** It only initiates the drain, and throws synchronously when the worker is not running.
  - The drain is complete when `worker.run()` resolves. Release shared resources, such as the stills/measure Chrome, after `run()` settles, never after `await worker.shutdown()`.
  - With two workers (the main `render` queue plus the engine render queue), call each `shutdown()` in its own try/catch, then await one shared `Promise.allSettled([a.run(), b.run()])`.
- **Smoke the worker lifecycle against local Temporal:**
  1. If :7233 is closed, start Temporal with `scripts/dev-native/up.sh`.
  2. Start the worker with `node --import tsx src/worker.ts`, with `.env` loaded, `NODE_ENV=development`, and a throwaway `RENDER_TASK_QUEUE` and `WORKER_RENDER_HEALTH_ADDR`.
  3. Wait for `worker ready` and for `/readyz` to return 200.
  4. Send SIGTERM and expect exit 0.

  The terminal tool refuses `&`, so put the start/kill sequence in a script file and run that.

## Composition-side upgrades (`packages/compositions/src/`)

- **Scope a one-composition upgrade with a grep-gate on the diff, not with discipline.** When the plan says "only this composition changes", enforce it: `git diff main --name-only | grep -vE '<allowed-path-regex>'` must return empty before pushing. The two accidental cross-composition changes to catch are (a) a shared primitive edit "to add one prop" that lands as a widened signature every sibling now depends on, (b) a package.json test-script edit that drops a sibling's spec from the chain. Put the regex in the plan header so reviewers can rerun it.
- **Extend shared primitives via EXISTING optional props, never a widened signature, when scoping work to one composition.** `primitives/Captions.tsx` already took a `chunks?: {startMs,endMs,words}[]` prop and a nullable `style`; the MotionGraphics-only upgrade threads TikTok-cadence pages through that existing opening. New required props on a shared primitive force every sibling composition (`VoiceOver`, `CaptionedClip`, `RedditStory`, `NewsRecap`, `AiClipReel`, `CharacterDialogue`, `Slideshow`, `StillImage`, `Transcript`) to be audited and re-tested — the one-composition scope evaporates. If an existing optional prop does not fit, wrap the primitive in a composition-local component and apply the new behaviour there.
- **Apply CSS the shared primitive inherits (letter-spacing, color, font-weight) on a wrapper `<div>` around `<SharedPrimitive>` rather than editing the primitive.** AbsoluteFill children inherit `letter-spacing`, `color`, `fontWeight` by default; the wrapper gives you a per-composition style override without touching the primitive. Confirm by checking the primitive and its highlight sub-components do not reset the property (`grep -n 'letterSpacing\|letter-spacing'` the primitive + every file under `caption-highlights/`); a highlight that sets its own letter-spacing on a text span makes the wrapper's value dead.
- **`node --experimental-strip-types` cannot load `.tsx` — `ERR_UNKNOWN_FILE_EXTENSION`.** `packages/compositions` runs specs via `node --experimental-strip-types --no-warnings <file>` so JSX files cannot be imported by a spec. Extract any logic you want to unit-test out of the `.tsx` component into a sibling `.ts` module (`captionPages.ts`, `mouthState.ts`, `punchIn.ts`) and spec that. The `.tsx` component's visual contract is covered by typecheck + a Phase-4-style determinism render test, not by `node --test`.
- **Under `--experimental-strip-types`, relative imports that bring a RUNTIME value need the explicit `.ts` extension; pure `import type { ... }` imports work extensionless because they are erased.** Pattern that bites: adding `import { helper } from '../duration'` next to a working `import type { Quality } from '../dims'` — the type import survives because strip-types elides it, the value import fails resolution the moment any test transitively imports the file through strip-types. Write new relative value imports as `'../duration.ts'` from the start; the compositions tsconfig has `allowImportingTsExtensions` so typecheck accepts both forms. Mixed extensionless/value imports already live in the tree, but do NOT widen one when strip-types is in the resolution chain.
- **`packages/compositions/package.json`'s `test` script enumerates spec files one-by-one with `&&`; there is no glob.** A new `src/<area>/<name>.spec.ts` is invisible to CI until you append it to the chain. Append the new path when you add the spec, not later. Keep the `__tests__/*.spec.ts` paths and the inline `src/.../*.spec.ts` paths visually grouped so missing entries jump out on a diff.
- **`fitText` / `measureText` from `@remotion/layout-utils` inside `useMemo` MUST include the fonts-ready flag in deps** — otherwise the first measurement under the fallback face is cached, the useMemo never recomputes once the real font loads, and the final MP4 ships typography measured against system-ui even though it's drawn in the loaded family. Pattern: `useMemo(() => fitText({..., fontFamily}), [text, fontFamily, safeWidthPx, fontsReady])`. Returning `null` before `fontsReady` on the render path is NOT sufficient — React still runs the memo on the pre-ready render and the cache survives the state flip.
- **`useFontsReady` must fail OPEN on a rejected font promise** (release the `delayRender` handle anyway). An offline / sandboxed test harness that rejects the Google Fonts fetch would otherwise wedge the whole render on the unlabelled 30 s `delayRender` timeout. Label the handle (`delayRender('motion-graphics:fonts')`) so a real stall surfaces as that string in the logs instead of an anonymous timeout.
- **`createTikTokStyleCaptions` from `@remotion/captions` preserves input order and emits one output token per input Caption that falls on the page.** Rebuild per-page `WordTiming[]` by walking the source words in lockstep with `page.tokens.length`; do NOT try to re-join on token text (whitespace is encoded into `text` as a leading space per the Caption shape, so round-trip comparison is fragile). Mark the last Caption of each turn with `pageBreakAfter: true` so pages never straddle turn boundaries when you chunk per-turn.
- **Phase-structured renderer upgrades: dispatch the adversarial reviewer in the BACKGROUND after each phase lands, continue with Phase N+1's branching only after it returns.** The reviewer verdict re-enters as a new message between turns; use the gap to tidy local state (git log, scope-check grep, pnpm test one more time), do NOT poll the transcript. If the review returns `REQUEST_CHANGES`, fix on the SAME branch, push a fix commit, and dispatch a per-fix-commit re-review — one reviewer per PR phase + one re-review per fix commit, per the always-on invariant in the main skill.
