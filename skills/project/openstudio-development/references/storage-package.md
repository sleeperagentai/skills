# packages/storage — one object-storage package, three bindings

`packages/storage/contract/keys.json` is the single source of truth for S3 key templates + fixtures. Bindings: `go/` (module `github.com/agentclip/openstudio/packages/storage`, minio-go), `ts/` (`@openstudio/storage`), `py/` (`openstudio-storage`, boto3). Each binding has a conformance test that asserts EVERY fixture in `keys.json` and fails loudly on an unknown key — adding a key means: edit the contract, add the builder in all three, add the switch case in all three tests.

## Rules

- Never string-build an S3 key (`fmt.Sprintf("workspaces/%s/...")`, template literals). Use the contract builders (`AssetKey`, `RenderOutputKey`, `SceneAudioKey`, `BrollKey`, ...). Grep `workspaces/` literals across go/ts/py/mjs before declaring a migration done — stragglers hide in fast-path branches of activities.
- `services/media` is a thin façade re-exporting `packages/storage` so existing Go callers don't churn. New Go code imports `packages/storage` directly; `services/visuals` does too (it never imported media).
- `Stat.Meta` keys are lowercased in every binding — MinIO canonicalises user metadata (`Source` -> `source`) and Go/boto3/aws-sdk would otherwise disagree.
- `IsNotFound` matches `NoSuchKey`/`NotFound` (and boto3 head_object's `"404"` Code) only — never "any 404": `NoSuchBucket` is also 404 and must surface as misconfiguration, not `exists=false`.
- The contract's `bucket` field names where a key is SERVED from (render outputs/revisions/subtitles/broll are copied to public); it is informational — bindings do not consult it. Renderers write the canonical MP4 to private AND copy to public under the same key, because the API builds `OutputURL` from the public base.
- The façade's `PresignedGet` rejects unknown bucket names (accepts configured names or `private`/`public` roles); never silently map unknown names to another bucket. Every binding has `Delete`; live tests clean up their `test/storage-*` objects.
- Live round-trip tests are gated on `STORAGE_LIVE=1` (Go `go test`, TS `pnpm test:live`, Py `pytest`) against the local MinIO. Run all three before committing a contract change.

## Go workspace wiring

- Nested module: `go work use ./packages/storage/go` AND a `replace github.com/agentclip/openstudio/packages/storage => ../../packages/storage/go` (path relative to each importer) in every module that imports it, transitively (`apps/api`, `apps/worker-core`, `services/media`, `services/visuals`). Build per module — root `go build ./...` fails under `go.work`.
- `go mod tidy` in one module can rewrite unrelated modules that were never tidy (e.g. `apps/scheduler`). Check `git diff -- '*/go.mod'` and revert incidental churn so the PR stays focused.

## TS binding

- pnpm workspace glob `packages/*` does NOT match the nested `packages/storage/ts`; add it as an explicit entry in `pnpm-workspace.yaml`.
- `ts/src/index.ts` is single-file (no relative imports) and the package SHIPS `dist/` (`tsconfig.build.json`, `prepare` script, conditional `exports` → `./dist/index.js`, `dist/` gitignored). Pointing `exports` at raw `.ts` only works on Node ≥ 22.18 with unflagged type-stripping and breaks `node dist/worker.js` in the image; verify with `node --no-experimental-strip-types -e "import('@openstudio/storage')"`. Dockerfile runs `pnpm --filter @openstudio/storage build` before compositions.
- TS `copy()` must URL-encode `CopySource` per path segment; minio-go and boto3 encode automatically, aws-sdk does not.
- Any new workspace package consumed by motion-renderer must be `COPY`'d (its package.json) into `docker/motion-renderer.Dockerfile` for the pnpm fetch layer.

## Bucket lifecycle policy

MinIO/S3 lifecycle rules keep the private bucket from filling forever. Policy lives in `packages/storage/go/lifecycle.go`; applied idempotently at `apps/api` boot (`mc.Storage().ApplyLifecycle(ctx, policy)`) right after `media.New(...)`, non-fatal on error.

- **Only TOP-LEVEL regeneratable-cache prefixes get prefix-scoped rules.** `openstudio-private`: `tts/` expire 30d (content-addressed cache, miss = re-synth), `broll/` expire 90d (b-roll clip cache). `openstudio-public`: no rules (published renders live forever; the publish flow copies to the public bucket, which naturally bypasses private-bucket rules). `openstudio-uploads`: `AbortIncompleteMultipartUpload` 7d only (completed uploads like influencer photos stay).
- **NEVER emit a `workspaces/` prefix rule — it would also match `workspaces/{ws}/assets/` which is user uploads, and S3 lifecycle filters support only literal prefixes (no `*`).** A single `workspaces/` rule for the "expire unpublished renders after 90d" tier is silent data loss on user uploads — the first support ticket post-launch. The user-uploads path (`workspaces/{ws}/assets/{assetId}.{ext}` emitted by `AssetKey`) MUST remain untouched by any lifecycle rule. A unit test MUST iterate `buildPrivateRules(DefaultLifecyclePolicy())` and assert that no rule's `RuleFilter.Prefix` matches `workspaces/ws_demo/assets/asset_123.mp4` (and ideally also `workspaces/ws_demo/renders/...`, `workspaces/ws_demo/visuals/...`, `workspaces/ws_demo/projects/p1/audio/scene_1.wav` — those are not covered in this policy either).
- **Workspace-scoped expiration needs TAG-based lifecycle, not prefix-based.** The correct fix for expiring `workspaces/{ws}/renders/` etc. is write-time object tagging (`tier=renders` / `tier=visuals` / `tier=audio`) + `Filter.Tag` on the lifecycle rule — that cleanly excludes assets without needing to enumerate workspaces. It is a separate PR because it touches every `Put` call site; prefix-based coverage of `workspaces/*` is the wrong shortcut.
- **`SetBucketLifecycle` REPLACES the live config.** A rule removed from code is removed from the bucket on next boot. The operator contract: do NOT hand-add rules via `mc ilm`; add them to `buildPrivateRules` / `buildUploadsRules` and deploy. The escape hatch for pausing a rule in an incident is env overrides (`PRIVATE_TTS_EXPIRY_DAYS`, `PRIVATE_BROLL_EXPIRY_DAYS`, `UPLOADS_INCOMPLETE_EXPIRY_DAYS`), not hand-editing MinIO.
- **Zero or negative days OMIT the rule, do not emit "days=0".** MinIO interprets `Expiration.Days: 0` as "expire now" — the AWS-common misconception that 0 means "never" is a destructive foot-gun. The builder filters out zero/negative days and emits no rule for that tier; env override of 0 is the incident escape hatch. Log an INFO line at boot for every omitted-by-env rule (`lifecycle rule disabled by env rule=... days=...`) so the paused state is visible in production logs — silent disable is ambiguous.
- **Env override parse errors must log WARN, not silently fall back.** `strconv.Atoi` failure on `PRIVATE_TTS_EXPIRY_DAYS=none` is an operator typo; defaulting silently means the operator thinks expiration is paused when it isn't. Emit `slog.Warn("invalid lifecycle env override — using default", "var", name, "value", v, "default", cur)` and keep the default.
- **Hoist rule-builders out of `ApplyLifecycle`.** `buildPrivateRules(p)` and `buildUploadsRules(p)` are pure functions that unit tests assert on without needing a real MinIO. A test can then prove: default policy emits all expected rule IDs; a zero override drops the matching rule; an all-zero policy emits nothing; user-asset keys are never matched.
- **`(*Client).ApplyLifecycle` returns a sentinel error on nil receiver, does NOT panic.** A boot-path function should fail loudly with `errors.New("storage: ApplyLifecycle on nil client")` rather than deref-panic; the caller logs and continues (non-fatal error path), matching the rest of apps/api's boot-wiring style. Panic in a boot function means the whole process dies on a nil the caller could have logged around.
- **Never set a lifecycle rule on the public bucket.** Even a defensive-looking empty config can replace rules an ops team set manually. Leave the public bucket's config untouched — `ApplyLifecycle` returns before touching it.
- **Non-fatal on error at boot.** A working storage layer with stale lifecycle is better than a boot failure. `slog.Error` on failure and continue; log the resolved day values so an operator can tell what the policy IS from boot logs, not just whether apply succeeded.

## Soft-delete sweeper pattern (`openstudio-uploads`, legacy drafts)

Standard pattern for scheduler jobs that remove stale objects — move to an archive envelope rather than hard-delete so an operator can recover a wrongly-flagged key with `mc cp`. The reference implementation is `apps/scheduler/archive_uploads.go` (`jobArchiveStaleUploads`).

- **Envelope shape: `_archive/YYYY-MM-DD/<original-key>`** in the SAME bucket. Leading underscore puts the archive below workspace-scoped keys in lex order; the date segment groups by sweep day so retention can age the archive itself out separately.
- **Copy-then-delete order.** `storage.Client.Copy` is a server-side S3 COPY (same bucket; a 1 GB object does not round-trip through the scheduler process). On a mid-sweep crash the archive key exists AND the original — strictly recoverable. The reverse (delete-first) would be data loss on a crash. Log a WARN counter on the Delete failure path so Grafana can alert on orphan duplicates.
- **`isSweeperEnvelope(key)` must match the FULL shape `_archive/YYYY-MM-DD/<non-empty>`, not just the `_archive/` prefix.** A workspace member with upload rights can `PutObject` under `_archive/evil.jpg`; a prefix-only skip means that key pins bytes forever (and gets accounted to the workspace's storage total). The envelope check requires: literal `_archive/`, then exactly 10 chars with dashes at positions 4 and 7, then `/`, then non-empty rest. Everything else — including bare `_archive/<key>` — IS swept. Lock this in with a unit test over cases: `_archive/2026-10-14/x` → true, `_archive/evil.jpg` → false, `_archive/NOT-A-DATE/x.jpg` → false.
- **The `_archive/` prefix is NOT itself swept by MinIO lifecycle in this PR.** Followup: add a 60-day lifecycle rule on `_archive/` so recovered-or-forgotten envelopes don't live forever. Until then, operators monitor by browsing `mc ls local/openstudio-uploads/_archive/`.
- **Env override parses as a BARE INTEGER, not a `time.ParseDuration` string.** The var name promises units (`UPLOAD_ARCHIVE_MAX_AGE_HOURS`), so an operator writing `12h` and the code doing `time.ParseDuration(v + "h")` produces `12hh` and silently falls back to default. Use `strconv.Atoi(strings.TrimSpace(v))` and WARN on parse failure — a typo must be visible, not treat-as-default.
- **`c.List(ctx, bucket, "")` drains the full ListObjects channel into a slice in memory.** Fine for buckets ≤ ~500k objects; a production bucket with millions OOMs the scheduler. Until a streaming `Walk(ctx, bucket, prefix, func(Object) error)` ships on `packages/storage`, bail with `slog.Warn("sweeper: bucket exceeds safe List threshold; add packages/storage.Walk()", "bucket", b, "listed", n, "threshold", 500_000)` so Grafana can alert.

## Per-workspace storage-usage tracking (nightly scheduler job)

`apps/scheduler/track_storage_usage.go` scans all three buckets, aggregates per workspace, writes one row per `(workspace_id, bucket)` per run to `platform.storage_usage` (migration 00057). `apps/api/workspace_storage.go` serves `GET /internal/workspace/storage` with `SELECT DISTINCT ON (bucket) ... ORDER BY bucket, computed_at DESC`.

- **Non-workspace-scoped prefixes (`tts/`, `broll/`, `_archive/`) aggregate under a synthetic `_shared` id and MUST NOT persist** — those are an infra concern, not a billing concern. `_shared` has no `platform.workspaces` row; the FK would reject the write. Skip the insert for `workspaceID == "_shared"` BEFORE the pool.Exec; operators read shared-bucket size from MinIO metrics, not from `platform.storage_usage`.
- **`workspaceIDFromKey` returns `""` for anything that isn't `workspaces/<ws>/<rest>`.** The caller buckets `""` under `_shared`. Edge case the test must cover: `workspaces/<ws>/` (dir marker, no body) IS owned by that workspace — don't accidentally send that to `_shared`.
- **FK violation on a deleted-workspace race is a SKIP, not an error.** Between `List` and `Insert`, a workspace can be deleted — the FK cascade purges `platform.storage_usage` rows for THAT workspace, but the pending insert still fails with SQLSTATE `23503`. The job must return `nil` on that row and continue, not surface it as a job failure. See references/schema-and-migrations.md for the typed `pgconn.PgError` + `pgerrcode.ForeignKeyViolation` check — do NOT use a `strings.Contains(err.Error(), "23503")` string match.
- **History retention: 90 days, purged by the same job.** `DELETE FROM platform.storage_usage WHERE computed_at < $1` on every run so the table stays bounded.
- **API endpoint returns an empty `buckets: []` for a fresh workspace / before the scheduler ran — NOT 404.** The dashboard renders a zero state without branching on absent-rows vs error.
