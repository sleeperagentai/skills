## Standing invariants (always on)

- **Never name a new source directory `data/` or `dist/`, and run `git check-ignore -v <path>` on every new directory before committing.** The root `.gitignore` ignores every `data/` and `dist/` at any depth, so files in them are silently left out of git and CI fails on a fresh checkout. The motion engine uses `tables/` and `gen/` for this reason; its schema/codegen, transcript, stage-runner, LLM-provider testing, manifest semantic-check, fixture, composition, package-layout, render-activity, CI/Docker-image/lint/lockfile, milestone-review and handover-document rules are in references/motion-engine.md. **Motion-graphics is codegen, not a kit (ADR 0019): the user's standing rules for it are in references/motion-engine.md § Codegen series — read that section before planning or touching `services/motion` / `packages/motion-engine`.**
- **A PRD or status doc is not a greenfield spec — verify what already ships before planning or marking work open.** PRDs reference sibling PRDs as "Related" and describe emitters/tables/routes as if they are future work, and `docs/PRODUCTION-READINESS.md`-style status lists flag items as open months after they shipped — the sibling or the item may already be live. Before writing a plan, opening a migration, or taking a status bullet at face value, grep `services/db/migrations/` for the sibling's tables, `apps/api/*.go` for its handlers (route table around `main.go` lines 400–700), `apps/web/components/` or `apps/web/app/` for the UI the bullet claims is missing, and `services/<domain>/` for its package; `ls services/db/migrations/ | tail -5` is a one-liner that tells you the next migration number and whether a referenced table landed. Planning on a stale PRD produces stub emitters, duplicate schema, or "implement X as well" scope that is already done.
- **"Review and merge" = adversarial review first.** One fresh-context reviewer per PR (delegate_task, leaf, read-only, given the per-module test commands and a `verdict` schema); fix every Critical/Warning, push follow-up commits, then a second fresh reviewer per fix commit before merging. Self-review has missed an unenforced sandbox and a flag that 400s pricing. Never merge on a self-report. Reviewer context must say in words: "unit tests only; never start the API; never call localhost:4000 or a vendor" — a reviewer told merely "no live-spend scripts" may still boot the stack to probe. Budget four to five rounds for anything touching user text or safety guards: each fix to a character/word filter opens its own edge, so keep fix commits minimal and scope each re-review to that commit. "Ensure all PRs are merged" is a sweep — follow references/pr-merge-sweep.md.
- **No feature flag without its pricing line.** A new `VisualProvider` name needs `services/pricing` `augmentLines[name]` + a `Compute` test, or flipping the flag 400s every augmented request.
- **Ship a feature complete end to end — never park the risky half behind a flag (standing user decision).** "Behind `FEATURE=off` until a test clip" is not a delivery option here; plan every leg (gateway, API, DB, scheduler, web, ADR) and build them in one branch. The one open question a vendor-facing leg leaves — how it is first exercised against the paid vendor — is asked ONCE, at the moment that leg is being planned ("ask when you get there"), not pre-answered with a flag and not asked up front with the rest of the scoping.
- **A pasted build brief or milestone plan is a REVIEW request until the user explicitly says "build".** First map the current path it replaces (provider routing, workflow, activity, composition) and grep for every capability it names. Then reply with: a current-vs-proposed table; where its "assumed present" or "decided" items do not match the repo; its internal faults (a milestone using something a later one builds, done-criteria that can never pass); and the decisions needed, recommended option first. Then stop. Do not branch, scaffold, install or start Milestone 1, and do not close by offering to build it a particular way — that gets rejected. Offering to write the reviewed plan as a doc is fine. Motion-graphics checklist: references/planning-multi-phase-work.md § Reviewing a proposed motion-graphics pipeline rewrite.
- **Multi-week PRDs: resolve the open-questions section and the session-scope BEFORE writing code.** A PRD with an `Open questions` block (§15-style) gates the schema shape and package layout: owned-vs-aggregator decides the `provider` CHECK and the `services/<x>` layout; scope-of-connection decides whether a column is workspace- or user-keyed; etc. Guessing those forces a rip-up migration later. Ask them as ONE `clarify` call with the PRD's recommendation listed first, together with "what slice of this PRD do you want shipped this session?" (common answers: migrations+ADR+OpenAPI only; vertical slice on fakes; vertical slice + one real provider; full PRD). This is the single clarify, not a chain — resolve blocking decisions in one round and start cutting.
- **No Docker on this VM.** Local infra runs natively via Homebrew — Postgres 5432, Redis 6379, MinIO 9000 (minioadmin/minioadmin, buckets openstudio-public/private), Temporal 7233 (queues `pipeline` for Go, `render` for Node), Mailpit 1025. Boot with `scripts/dev-native/up.sh`.

- **Money is integers only.** No floats for credits, prices, or amounts.
- **No SQL outside `services/db`.** All persistence goes through that package.
- **Compositions stay TypeScript.** Remotion lives in `packages/compositions` — never rewrite a composition in Go.
- **Goose migrations start at `00001`, not `00000`.** Scaffolders emit `00000` and goose skips it silently.
- **User-facing surfaces never leak technical strings.** Never surface raw LLM prompts, `[fake:...]` provider markers, JSON blobs, workspace/user IDs, endpoint paths, or `Preview soon` placeholders in UI text a real user sees. If a real value isn't ready, either produce a plausible substitute server-side or hide the surface entirely — indefinite `coming soon` labels are shipped placeholders, not neutral UX.
- **Real third-party brand marks on third-party surfaces, not lucide stand-ins (standing user rule).** When the UI references a real external platform or service (YouTube, TikTok, Instagram, Snapchat, Stripe, Spotify, etc.), use that platform's actual logo and brand colour, not a shape-vaguely-similar lucide-react glyph (`Video` for YouTube, `Music2` for TikTok, `Share2` for Instagram, `Camera` for Snapchat is what the first draft shipped — the user asked for real logos the next turn). lucide-react v1.48 does NOT export `Youtube` or `Instagram` as components, which is the trap: typing `import { Youtube } from "lucide-react"` fails, and the next move is to grab the nearest shape rather than reach for a real mark. The right pattern is to vendor the Simple Icons SVGs (CC0 1.0) directly as inline React components in `apps/web/components/publish/platform-glyph.tsx`-style modules — no dependency, path is `currentColor`, wrapper sets the brand hex (YouTube `#FF0033`, TikTok `#000000`, Snapchat `#FFFC00`, Instagram the three-stop gradient `linear-gradient(45deg, #F58529 0%, #DD2A7B 50%, #8134AF 85%, #515BD4 100%)`). Snapchat yellow needs a near-black glyph for contrast; everyone else is white. One shared `PlatformTile` / `PlatformBadge` pair keeps every surface consistent so the Connections cards, publish drawer, and publication strip all render the real marks. Download the SVGs from simpleicons.org when adding a new platform — never trace by hand.
- **Auth-gated endpoints fail closed — never synthesise a placeholder identity.** A handler that falls back to a demo user/workspace when no session is present (`demo@openstudio.local`, `ws_demo`) returns 200 to an unauthenticated caller, so every downstream page renders fake identity instead of bouncing to sign-in, and a genuinely broken session looks like a working one. Return 401 and let the frontend redirect. Enforcement is per-handler, so it drifts: when one identity endpoint 401s and a sibling returns 200 with data, the 200 is the bug. Probe every session-scoped route with no cookie after touching any of them — a bare `curl -s -o /dev/null -w '%{http_code}'` sweep catches the drift in one pass.
- **Provider errors are for logs, not users.** Never `WithDetails("error", err.Error())` on an ai-gateway or provider failure — that ships the raw `anthropic 404: {"type":"error",...}` payload (with model IDs, request IDs, prompt fragments) to the UI. Log the full error server-side (`slog.Error(...)` with structured fields) and return a plain sentence to the client ("Couldn't generate a script right now. Please try again."). Same rule for stack traces, SQL errors, S3 object keys. Audit ALL live handlers together — fixing one leaks in another (e.g. `writeErr(w, errs.From(out.err))` in `/live/tts/turns` while `/live/tts` is already sanitised).
- **External-provider `/live/*` endpoints need per-workspace rate limits.** A runaway client (or an infinite Temporal retry loop, or a UI in a fetch loop) burns paid TTS/LLM quota within minutes. In-memory fixed-window (`live_ratelimit.go`, ~60 calls/min/workspace, configurable via env like `LIVE_TTS_PER_MIN`) is enough for single-node dev; swap for Redis when sharding. Gate the handler BEFORE parsing the body — short-circuits on abuse without paying the JSON-parse cost. Return 429 with `Retry-After` header.
- **First-boot secrets: three env vars must be ≥32 bytes or the API refuses to start.** `AUTH_SESSION_SECRET`, `API_KEY_HMAC_SECRET`, `WEBHOOK_HMAC_SECRET` — shorter values (or empty) exit with `config: configuration error; invalid: <var> (must be >=32 bytes in production)`. `ENVIRONMENT=development` does NOT relax the check. Boot script snippet:

```bash
export AUTH_SESSION_SECRET=$(openssl rand -hex 32)
export API_KEY_HMAC_SECRET=$(openssl rand -hex 32)
export WEBHOOK_HMAC_SECRET=$(openssl rand -hex 32)
```

Stable dev values go in `.env` (already git-ignored); rotate for prod. Missing them is the #1 cause of "api starts and immediately exits with exit status 1" on a fresh clone.
- **Never load `.env` contents into your own context once operator secrets are in it.** `stat`, `grep -c <pattern> .env`, `wc -l`, and `awk -F= '/^KEY=/ {print NF>0}'` are safe — they return existence/shape, not values. `cat`, `read_file`, `head`, `tail`, and bare `grep` pull `ELEVENLABS_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, the three HMAC secrets, and any voice-id defaults straight into the conversation transcript, where they persist across delegations and log dumps. When verifying an operator's `.env` change, issue the API call whose failure was the trigger and read the raw response from `/tmp/os-logs/api.log` — do NOT diff the file. `.env.example` is the correct target for schema/layout questions; the real `.env` is opaque by policy.
- **`.env` loads in-process via `services/config.LoadDotEnv()`, not `source`.** Both binaries (`apps/api`, `apps/worker-core`) call it at the top of `main()` before any env read; runtime env keeps priority, missing file is fine, first `.env` walking up from cwd wins. Never instruct operators to `source .env` — provider keys in `.env` must work with a plain `go run ./apps/api`. **After editing `.env`, restart EVERY process that already loaded it — API, worker-core, worker-render, `next dev`.** Env is read once at startup and cached in the process; a previously-booted API keeps sending requests with the OLD `ELEVENLABS_API_KEY` / `ANTHROPIC_API_KEY` / `TEMPORAL_NAMESPACE` even though the file on disk has the fix. Symptom: same 401/402/404 error persists after the user says "done" and the file mtime confirms the edit. Restart all four before re-testing, then diff the `aigw:` startup lines to confirm the new resolution took.
- **Node subprocesses (`apps/worker-render`, `apps/web`) load `.env` themselves — pnpm/tsx do not inherit repo-root env.** Every Node entrypoint runs in-process dotenv against the repo root before any config read: `dotenvConfig({ path: path.resolve(process.cwd(), '../../.env'), override: false })` at the top of `src/worker.ts` / the Next.js layout (`override: false` so runtime env still wins). Not `tsx --env-file-if-exists` (swallowed as a positional arg) and not `node --env-file` (fails on shape mismatches).

The project is created when the user submits the FIRST wizard step, its id goes in the URL (`/projects/{projectId}/create`), and every later step and service call is scoped to it. Full recipe + director-sidecar public/ download + testing + OpenAPI shape in **`references/static-asset-catalogue.md`**.

- Before planning a schema addition, grep `services/db/migrations/*.sql` for the target table; the initial schema is denser than the plan usually assumes. Confirm the exact column list with `psql "$DATABASE_URL" -c '\d platform.<table>'` before writing a query — grepping the migration that CREATEd the table misses later `ALTER TABLE ... DROP COLUMN` migrations, so a column that appears in the creating migration may no longer exist.

**A forward-compat column's CHECK constraint lists only values the running stack actually serves — not every value the schema might ever accept.** Example: a `provider TEXT NOT NULL DEFAULT 'owned'` column meant to someday also carry `'late' | 'bundle'` must `CHECK (provider IN ('owned'))` today, so adding an aggregator later is a migration (new allowed value + the adapter wiring) rather than a silent code flip against a schema that already "allowed" it. Keeps the schema honest about what the running code can serve, and prevents a row being written for a provider nothing can execute against. Same rule for `kind`, `platform`, `status` enum-style columns.

**Vendor-mediated features: keep the owned-shape canonical table AND add parallel `*_aggregator` sibling tables with an `aggregator` COLUMN (standing user rule).** For any multi-provider seam that may route through aggregators now and move to owned adapters later (social publishing, future distribution/analytics vendors): the canonical `content.<entity>` table stays shaped for the eventual OWNED-adapter rollout per platform — per-platform native identifiers, encrypted-token columns, platform-native metric columns. Aggregator-specific data lives in a SIBLING `content.<entity>_aggregator` table (one row per aggregator-mediated canonical row) carrying `aggregator TEXT NOT NULL CHECK (aggregator IN ('zernio', ...))` + `raw JSONB NOT NULL` for the vendor's full response verbatim. Why: (1) when a platform moves aggregator→owned the canonical row keeps its shape and the sibling row becomes empty — no rip-up migration; (2) a workspace can run multiple aggregators side-by-side without column proliferation (aggregator is a column, not a table name); (3) raw payloads enable metric backfill when a new typed column is added and vendor-swap forensics. One profile per `(workspace, aggregator)` pair in `platform.workspace_aggregator_profiles` (PK `(workspace_id, aggregator)`) — lazy-created on first Connect. `*_aggregator` RLS scopes through the parent canonical row's `workspace_id`, not its own column (same shape as `content.series_episodes` in 00006). Same pattern for metric snapshots: canonical `*_metrics` with normalised typed columns, `*_metrics_aggregator` with `raw JSONB` so a new metric column can be backfilled from history. **Alias BOTH tables in every list/get join query — `id` is ambiguous.** The canonical and sibling tables each carry `id`, so a decorator subquery like `WHERE publication_id = content.publications.id` (unqualified `id` on the right of the equality is fine) silently works, but the moment the join aliases the parent or references `id` in the outer SELECT, Postgres returns `column reference "id" is ambiguous (SQLSTATE 42702)` at runtime. `go test` is green because tests seldom exercise the join path with the sibling table attached. Shape every list/get query as `FROM content.<entity> p JOIN content.<entity>_aggregator ... ON ...` and reference `p.id` throughout; name the metrics subquery's alias too (`FROM content.publication_metrics pm WHERE pm.publication_id = p.id`). Only a live first call surfaces this one — budget a smoke-GET per endpoint after the schema lands.

**Build-vs-buy for multi-platform/multi-vendor seams: present the honest tradeoff BEFORE writing code.** The user asks "how do these providers make it work? is it much work to build internally?" when faced with an aggregator option — answer by naming what the vendor eats (per-platform developer apps, OAuth token custody, quota accounting, API-change churn, audits with weeks-to-months calendar cost), what owned-adapter code would actually be (per-platform LoC estimate, token refresh, error taxonomy, per-vendor quirks like Instagram's public-URL requirement or TikTok's disclosure booleans), and the audit calendar (YouTube 4-8 weeks, TikTok 2-6 weeks, Instagram 3-8 weeks, Snapchat 8+ weeks and invite-only). The audits BLOCK public launch, not the code — never present owned-only as a one-session deliverable, "all connections work" is a lie without them. Recommend aggregator-first with the owned-adapter Provider INTERFACE in place so individual platforms can swap later (one user-visible reconnect per platform). This complements the two-tier schema above: the schema is already shaped for the swap.

**Nested + flat routes coexist when the PRD specifies one shape and prior clients ship another.** Mount BOTH when PRD §Routes names `POST /api/v1/parents/{id}/children` and a shipped version already uses `POST /api/v1/children?parentId=...` — the existing clients keep working while new work follows the PRD. The handler reads the parent id as `chi.URLParam(r, "parentId")` and falls back to `r.URL.Query().Get("parentId")`; the PRD-shaped body is the one source of truth for payload fields, the query-string form is a thin shim. Pair this with the two-tier `*_aggregator` rule above: both the flat and nested routes return the same decorated-join DTO, so the ambiguous-`id` fix applies to both.

**OpenAPI edits: route defs before `components:`, schemas before top-level `security:`, then validate.** `docs/openapi/openstudio.yaml` has two insertion points for new work: `paths:` entries go directly before the `components:` block; new `components.schemas` entries go directly before the top-level `security:` block at EOF. After editing, confirm the YAML parses and every `$ref` resolves with a one-liner:

```bash
python3 -c "import yaml,re; d=yaml.safe_load(open('docs/openapi/openstudio.yaml')); s=set(d['components']['schemas']); r=set(re.findall(r'#/components/schemas/(\w+)', open('docs/openapi/openstudio.yaml').read())); print('missing:', r-s)"
```

A non-empty `missing:` means a `$ref` points at a schema that doesn't exist — fix before committing or the generated SDK/typecheck breaks downstream.

**A migration that creates a table must also hand it to the app role.** Goose runs as the superuser (`sa-vm`), so a newly created table is owned by that role and the `openstudio` connection role gets `permission denied for table <name>` at runtime — while `\d` shows the table present and correctly shaped, which makes it read as a query bug rather than a grants bug. Every CREATE TABLE migration ends with the ownership/grant block (canonical form in migration `00012`):

```sql
ALTER TABLE platform.<table> OWNER TO openstudio;
GRANT SELECT, INSERT, UPDATE, DELETE ON platform.<table> TO openstudio;
```

**Forgetting the `OWNER TO openstudio` line is silently poisonous.** `goose up` succeeds (whoever ran it owns the new table), the schema looks fine, but every app INSERT then fails with `new row violates row-level security policy for table <t>` — because the app's connecting role is NOT the table owner, so the decorative `tenant_isolation` policies suddenly bite. Symptom in tests: a brand-new store or handler test blows up on the first create call while every other table works. Fix: patch the migration to add the `ALTER TABLE … OWNER TO openstudio` and run `goose down` + `goose up` to re-apply.

**Quote or rename reserved-word column names before the migration lands.** Postgres rejects unquoted `row`, `user`, `order`, `end`, `window`, `offset`, `check` as column identifiers; `goose up` fails on the CREATE TABLE with `syntax error at or near "row"` and leaves the migration half-applied. Rename to a non-reserved form (`row_slot`, `username`, `ord`, `ends_at`) at authoring time rather than double-quoting — the quoted form forces every SELECT in Go code to double-quote too, which is easy to forget.

**RLS in this repo is currently decorative on the app path — do not rely on it for isolation.** Most `content.*` tables carry `tenant_isolation` + `service_bypass` policies, but the app connects as `openstudio`, which **owns** those tables and therefore bypasses RLS; `openstudio_app` and `openstudio_service` both have `rolcanlogin = false`; and nothing in the codebase calls `set_config` to populate `platform.current_workspace()`. Tenant isolation is enforced by `WHERE workspace_id = $1` in `services/db`, not by Postgres. Write new policies correctly anyway so that tightening the connection role later does not break reads — but when adding **public** rows (`workspace_id IS NULL`), check the existing policy predicate first: `content.characters` had only `public_presenter_read` scoped `(workspace_id IS NULL) AND (is_presenter = true)`, so public non-presenter rows would have been invisible the moment RLS became real.

**A data migration's `UPDATE ... FROM` join needs an explicit scope and a tie-break.** Linking `catalog.items` to `content.characters` on `voice_id` silently picked an arbitrary row where three characters shared `voice_seed_narrator` — and the winner was a tenant's demo character, so the public catalog ended up referencing workspace-scoped data (a cross-tenant leak, not a cosmetic mismatch). Scope to `workspace_id IS NULL` and use `SELECT DISTINCT ON (key) ... ORDER BY key, id` for determinism. Then **`SELECT` the result and read it** — the migration reported success and the wrong rows were only visible by inspecting the join output.

Verify after `goose up` by issuing the query as the app role, not as the superuser: `psql "postgres://openstudio@localhost:5432/openstudio?sslmode=disable" -c 'SELECT 1 FROM platform.<table> LIMIT 1'`. Testing as `sa-vm` passes and proves nothing.

## API-side safety middleware (shared stage guard)

**`if p == nil` is a dead auth check — `principalFrom()` never returns nil.** It returns a non-nil EMPTY `&auth.Principal{}` when the request context carries none, so a guard written as `p := principalFrom(r.Context()); if p == nil { 401 }` compiles, reads as fail-closed, and admits every unauthenticated request — which then queries with `workspace_id = ""`. Two live instances were found this way: `handleListPresenters` returned **200 with the full presenter catalog** (ids, names, voice ids, sprite URLs) to a request carrying no credentials, and `handleGetPresenter` only 404'd by luck. Always check `p.UserID` and `p.WorkspaceID` explicitly. `apps/api/unauth_sweep_test.go` guards two layers: a live sweep asserting each workspace-scoped handler refuses an unauthenticated request, plus a source-level scan that FAILS when any non-test file in `apps/api` adopts the bare form (exempting `hasScope`, a pure helper that legitimately nil-checks its argument). The source-level scan is NAIVE — it matches `if p == nil` anywhere, regardless of whether `p` is a principal or an unrelated `*string`/`*Config`/etc. In new handler files, name non-principal pointer parameters anything other than `p` (`sp`, `cfg`, `acc`), and if a helper takes the principal as `p` and does its own `p.UserID == ""` check, hide the dead-nil-guard temptation by having the helper return early via the UserID check instead of a nil check. The scan also fires on GENERIC helpers whose first type parameter happens to be a pointer — e.g. `func derefOr[T any](p *T, base T) T { if p == nil { return base }; return *p }`. Rename the parameter (`sp` / `override` / `ptr`) so the scan sees `if sp == nil`; the helper is correct, the scan just reads naively. One session rename-dance (3× for one file) is cheaper than discovering the scan on `go test` after each push.

**`readBody` silently TRUNCATED oversized bodies — that was a moderation bypass, not a style nit.** It allocated exactly `cap` bytes and stopped reading, returning the prefix as if complete. A truncated JSON body fails to parse, so a moderation-text extractor returns `""` and the request skips content screening entirely. Now reads `cap+1` and rejects on overflow. Any bounded-read helper must error rather than trim.

**Chain order: auth → rate limit → bounded body read → moderation → reserve credits.** Rate limiting precedes body parsing so an abusive client cannot make the server pay JSON-decode cost per request; moderation precedes credit reservation so nothing is reserved against a request about to be rejected. One composable chain (`apps/api/stage_guard.go`) applied identically to every stage — per-handler drift has bitten this repo twice (`/live/tts` sanitised while `/live/tts/turns` leaked; sign-in posting a path the API never served).

**The `[[block]]` keyword tripwire must run unconditionally, BEFORE the provider.** An earlier version consulted it only when no moderation provider was wired, so wiring a permissive provider silently disabled it — backwards, since the tripwire exists precisely because a permissive or fake provider waves content through. Note the fake provider matches on a **prefix** while `stubModerate` matches on a **substring**, so a mid-string marker passes both unless the tripwire runs separately.

**Moderation fails CLOSED; the Laya prefilter fails OPEN.** Opposite failure semantics by design: when the authoritative provider errors you do not know whether the content is safe, so refuse with a retryable message; when the local prefilter errors or returns a degraded score, log and fall through, because blocking would take down all traffic on a misconfigured box. Encode the asymmetry explicitly or someone will "simplify" both paths into one.

**A ledger contract has FOUR outcomes, not two — the forgotten one is the failed optional augmentation.** Reserve before provider spend, resolve exactly once after: success → `Settle(actual)` (may be below estimate; refund the difference); failed before any spend → `Release()`; failed after partial spend → `Settle(spent)`; **optional augmentation failed → `Settle(price_without_augmentation)` and still ship the output**; worker abandoned → `Expire()` sweeps it. Row four mirrors the existing invariant that a failed b-roll/cover-art degrades to the un-augmented render — if the credit path does not match, a $0 provider balance bills the user for enrichment they never received. Settlement clamps to the quote (the user only ever saw the quote) and logs a warning when the clamp fires, since hitting it means a stage's cost computation disagrees with its own quote. Test by asserting the **workspace balance** after each path, not that a ledger call happened — balance is what catches a release that settles or a settle that charges the estimate — then call `Invariants(ctx, ws)`, which is what catches a reservation left held forever.

**Match ledger insufficient-credit errors by CODE, not by the sentinel.** `ledger.Reserve` returns a bare `errs.New(errs.CodeInsufficientCredits, …)` that does **not** wrap `ledger.ErrInsufficient`, so `errors.Is(err, ledger.ErrInsufficient)` is always false. `AppError.Is` compares by `Code`, so `errors.Is(err, errs.New(errs.CodeInsufficientCredits, ""))` is what works. Refuse underfunded workspaces at reservation time with 402, before any provider call.

**The API wired `ledger.NewMemStore()` unconditionally — credits lived in process memory even with Postgres up.** `billing.credit_lots`, `billing.reservations` and `billing.ledger_entries` have existed since the initial schema and `ledger.NewPgStore(pool)` was fully implemented, but nothing connected it: reservations vanished on restart, `Expire()` had nothing durable to sweep, and two API instances would disagree about the same workspace's balance. Now swapped in the `if db != nil` branch of `newState`, which logs `ledger=postgres`. When verifying a credit flow, check `billing.reservations` in Postgres (`status` goes `held` → `settled`), not just an in-process balance — a MemStore balance that moves proves nothing about production.

**A fail-closed timeout is a DoS knob pointed at yourself — size it for the SLOWEST provider you support.** `stageModerationTimeout` started at 5s, fine for cloud moderation (sub-second) but it failed closed on *every* stage-1 request against a working local provider: Qwen2-VL-7B on CPU measures 3.4s for a trivial prompt and more for a real moderation question with a category list. The guard behaved correctly and the feature was unusable. Now 30s via `STAGE_MODERATION_TIMEOUT_SEC`. Symptom to recognise: `stage guard: moderation provider failed; failing closed` with `context deadline exceeded` while a manual curl to the provider succeeds. Related trap: `localvision.Reachable()` only GETs `/models`, so a wedged 6-day-old `llama-server` passes the boot check and still gets wired as the authoritative provider.

**Moderation resolves to a SEPARATE local server from TextGen — `LOCAL_VISION_URL` (default `:8081`), not `LLAMACPP_URL` (`:8080`).** Booting only the text model leaves the guard with `dial tcp :8081: connect: connection refused` and every stage fails closed with the sanitised "We couldn't check this request right now" message, which reads as an application bug. The `localvision` adapter sends a **text-only** OpenAI-compatible chat request for moderation (`image_url` content parts are optional and unused on that path), so point it at the text model already running instead of loading a second large model:

```bash
LOCAL_VISION_URL=http://localhost:8080/v1
LOCAL_VISION_MODEL=qwen2.5-3b
```

One 3B model then serves both capabilities and answers a real moderation prompt in ~7s. Two 7B-class models sharing one CPU is what pushes moderation past even a 30s budget — if a stage intermittently fails closed under load, check how many local servers are competing before raising the timeout again.

**A capability reachable at boot is not reachable at runtime, and the factory's fallback is a safety hole — the mechanism is the `NewAuto()` rule under Provider adapters below.** Verify the guard actually screened a request rather than skipping it: `grep 'no moderation provider wired' /tmp/os-logs/api-*.log` must be empty, and the row in `content.quality_scores` must carry `vendor_id=local:laya-minilm` with `degraded=f`.

## Audio pipeline (services/tts)

**`ffprobe` CANNOT read duration from a pipe — it needs a seekable file.** Measured on the same bytes: `ffprobe … /tmp/t.mp3` → `2.000000`, `ffprobe … pipe:0` → `N/A`. MP3 duration comes from the frame count, which requires seeking to the end; WAV and MP4 fare no better. `N/A` fails `ParseFloat`, so a stdin-piping probe errors on EVERY call and callers fall through to their estimate — silently, because the fallback is plausible. Both pre-existing copies of this helper piped on stdin, so the "mandatory ffprobe step" for ElevenLabs audio had never actually run and every ElevenLabs duration was a ~180ms/word guess. `tts.ProbeDurationMs` writes a temp file. Only a test asserting a KNOWN duration catches this class of bug.

**Never sum segment durations for a stitched total — probe the stitched file.** MP3 frame padding means concatenation yields more than the sum of parts. Measured: 4 × 1s segments give summed=4000ms, probed=4134ms (drift −134ms); a live 2-segment stage-2 call gave summed=2414ms probed=2461ms. Drift accumulates per segment until captions sit visibly off the audio. `tts.StitchResult` returns `DriftMs` so a caller can tell when per-segment offsets have stopped being trustworthy.

**ffmpeg concat with `-c copy` fails when a segment's real container does not match its declared MIME type** — `Invalid audio stream. Exactly one MP3 audio stream is required.` `FakeTTS` returns WAV-ish bytes labelled `audio/mpeg`, and real providers can too. Try stream copy, then fall back to re-encoding (`-c:a libmp3lame -ar 44100 -ac 1 -b:a 128k`): normalising whatever arrived beats failing a stage whose audio has already been paid for.

**An empty `wordTimings` array renders as a video with NO captions.** Captions are baked into pixels by the composition, so there is no error — just a product that looks broken. `tts.WordTimingsFor` prefers real ASR, rejects `FakeASR`'s exact `["fake","transcript"]` signature (matched on SHAPE, not on `AI_PROVIDER_MODE`, so it still fires when one capability falls back), and otherwise distributes the known text evenly across the known duration. Per-segment ASR timings are segment-relative — offset them or every segment's captions restart from zero.

**Validate uploads by PROBE, never by declared Content-Type.** A caller can label anything `audio/mpeg`; the type allow-list is only a cheap pre-filter. Without the probe a non-audio file reaches the renderer and fails there, after the user was told the upload succeeded. Order matters too: run caller-fixable validation (type, empty body) BEFORE infrastructure checks (db, media client), or every user mistake returns 500 and sends them looking in the wrong place.

**Content-addressed uploads must treat a duplicate as idempotent, not an error.** With a unique index on `(workspace_id, s3_key)` and a content-hash key, re-uploading the same file collides by design — so `ON CONFLICT DO NOTHING … RETURNING id` plus a fallback read of the existing row, not a 500 for an operation that already succeeded. Never put a user-supplied filename in a storage key (path games); keep it for display and sanitise it for echo and logs.

**Keep user uploads in their own table and S3 prefix.** `content.assets` rows are content-addressed and regenerable (a lost object costs one provider call); an uploaded file is the user's only copy. Sharing a table means a cache-eviction policy written for generated audio destroys user data. Hence `content.external_audio` + `external/`, distinct from `tts/` and `stitched/`. `project_id` is NOT NULL with `ON DELETE CASCADE` — every upload belongs to a project, because the wizard creates one before any stage runs. Soft-delete the row, and keep `done-with-no-timings` (silent audio) distinguishable from `failed`.

## Integration verification (what only a live run finds)

**Run the full pipeline against the real stack before believing it works.** Every bug below passed the complete unit suite. A live three-stage run found all of them in one afternoon:

- **`ffprobe` cannot read duration from a pipe** — so the "mandatory" duration probe had never run in this codebase (see the audio section).
- **An unchecked type assertion in a request path kills the process.** `StartRender` did `in["RenderID"].(string)`; stage 3 sent `"renderId"` (lowercase d, matching every other JSON field) and took the API down on its first real request. `map[string]any` crossing a JSON boundary makes key casing a convention, not a compiler-checked contract — resolve such keys through a tolerant helper, never a bare assertion.
- **ElevenLabs caps concurrency at 3** and returns `429 concurrent_limit_exceeded`; four parallel segments failed every multi-segment script. Size worker pools BELOW the provider ceiling (2 here) because `/live/tts` and the render worker draw on the same account. Retry throttles with backoff — a concurrency limit is transient — but never retry a 402: out-of-credit is permanent for that request.
- **A nil dependency panics mid-render, after ffmpeg has done minutes of work.** `r.Media.PutPublic` sat in a block whose own comment said "non-fatal". Check dependencies ONCE at the function boundary so a misconfiguration is a clear error before any expensive work; a panic in a Temporal activity takes the worker and the render with it.
- **A renderer that re-synthesises audio it was handed** bills the user twice, replaces their character's voice with the fake provider, and discards the stitched timing the captions were aligned against. `render.Input.PreRenderedAudio` is used verbatim; a zero duration is probed, not trusted. Refuse outright when there is neither supplied audio nor scenes — otherwise ffmpeg fails opaquely on an empty concat list, or worse succeeds into a silent video.

**Credits must be resolved on a context that OUTLIVES the request.** Every stage used `r.Context()`, so a timed-out render logged "releasing" while Postgres kept the reservation `held` — the write was cancelled and the error swallowed by `_ =`. All seven sites across three stages were affected, so assume systematic rather than a slip. Use a detached, bounded context (`creditCtx()`), log resolution failures, and add a structural test that fails if any handler reverts — the bug is invisible until a request actually times out.

**`ledger.Expire` only swept credit LOTS, never stale reservations.** A crashed worker held a user's credits forever: `Balance()` stayed reduced, later requests were refused as underfunded, and nothing errored. Age reservations against the STORE's clock, not the caller's `at` — `at` is a lot-expiry cutoff a caller may legitimately set far in the future, and using it for reservation age sweeps every in-flight hold. The negative test ("a fresh reservation survives a sweep") is what catches that; the abandoned-reservation test alone passes with the broken comparison.

**An endpoint sweep earns its keep on the first run.** Curl every path the frontend sends plus every new endpoint, treating 404/405 as a dead route. It immediately found `GET /internal/keys` with NO auth check returning the workspace's whole API-key inventory (ids, names, `sk_live_` prefixes, scopes) to an anonymous caller, and `POST /internal/keys` defaulting to `ws_demo` so an anonymous caller could MINT a working key. See `scripts/endpoint-sweep.sh`; allow an explicit expected-status override for routes that legitimately 404 on a nonexistent resource, or the script reports working handlers as dead.

**Check that a "keyword tripwire" actually contains keywords.** `apps/api/live_moderation.go`'s `blockKeywords` held exactly one entry — `"[[block]]"`, a test marker — so the always-on check that runs before Laya and before any provider screened nothing real. Tests passed because they only ever asserted the marker. When a safety list is the floor beneath everything else, pin it in BOTH directions: harmful inputs blocked AND legitimate topics allowed. Bare `"sarin"` blocked "the sarin attack on the tokyo subway, a news retrospective" — same false-positive lesson as Laya's nuclear power station. Keep substring lists short and high-precision; semantic nuance belongs in Laya.

**A verification script's cleanup glob must not match the file the caller redirects into.** `rm -f /tmp/pr-*.txt` at the top of the script deleted the `> /tmp/pr-run.txt` the operator had just redirected stdout into, so the run reported a bare "No such file" instead of its own result. Clear FIXED artefact paths, or namespace the cleanup glob away from anything a caller might plausibly use for output.

**A verification script that cannot fail is worse than none — it manufactures a green signal.** `three-stage-e2e.sh` exited 0 twice with stage 3 completely broken because its last command was a `psql` query rather than a status check. Re-run with the API stopped, it printed "PASS — all three stages produced a deliverable" by parsing LEFTOVER `/tmp/e2e-*.json` from three runs earlier. So: `rm -f` fixed temp paths before anything reads them; probe `healthz` first so a connection refusal is reported as "no API" rather than blamed on a stage (the endpoint sweep would otherwise report 30 dead routes for one missing server); accumulate failures through a `fail()` helper and `exit 1` with a count. Assert on substance too — a render that exists but fails QC or has no audio track is not a pass, and a reservation left `held` is a credit leak.

**Verify the CLIENT's request sequence, not the stage endpoints in isolation.** A green stage-by-stage E2E proves each endpoint works when called directly and says nothing about the path the UI takes — different route (the wizard posts `/api/v1/...` with a session cookie, not `/internal/...` with a key), different handler for the same concept, and different payload (the wizard sends `kind`, `script.mode`, `voices.mode`, `aspectRatio`, `templateId`; omit any one and the create 400s on a field the UI always supplies). Keep a second script that replays the client's exact sequence end to end and asserts the data crossing each hand-off is persisted. Six consecutive failures of that script were all real: wrong handler, clobbered settings, and four payload fields the direct-endpoint script never exercised.

**Read each live-run failure before changing anything — the cheap causes come first.** The repeating order on this stack: a dependency not running (`connection refused`), a fixture left over from an earlier run, a payload field the client sends and the probe does not, then finally the code. Re-reading the API log for the raw cause (the user only ever sees the sanitised message) beats guessing at the handler, and a restarted API will not pick up either a `.env` edit or a recompile without a restart — confirm the process start time is newer than the file mtime before concluding the fix did not work. **A background pipeline's reported PID is the pipeline parent, not the binary.** `/path/to/bin 2>&1 | tee /tmp/x.log` returns the tee's PID; a plain `kill <pid>` kills tee while the Go process keeps listening, so the next rebuild silently fails to bind the port and you re-exercise the OLD binary without knowing it. After kill, verify with `lsof -iTCP:<port> -sTCP:LISTEN`; if the port is still held, `pkill -f /path/to/bin` targets the binary directly.

## Provider adapters (services/ai-gateway)

**`factory.NewAuto()` starts from `aigw.NewFake()`, so a missing API key leaves a WORKING FAKE in the slot, not `nil`.** `FakeModeration` approves everything except text prefixed `[[block]]`, and `stageGuard` trusted it as an authoritative pass. When checking "is a real provider wired", a `nil` check is not enough — detect the fake by `Name()` (not a type assertion, so a wrapped/decorated fake is still caught) and fail closed when `APP_ENV=production`.

**Anthropic SSE is not OpenAI SSE, and the mismatch fails silently.** Named events (`event: message_start`), text only in `content_block_delta`, no `[DONE]` sentinel (ends at `message_stop`/EOF), and usage SPLIT across `message_start` (input tokens) and the final `message_delta` (output tokens). An OpenAI-shaped parser yields zero deltas with no error, because every line still starts with `data:`, the JSON still parses, and `choices` is merely absent. Exclude `thinking_delta` and `input_json_delta` explicitly or reasoning/tool JSON is spliced into the script and TTS reads it aloud. Handle `error` frames: they arrive AFTER a 200, so an overloaded_error otherwise reads as a short successful script.

**`http.Client.Timeout` caps the WHOLE response including body reads — strip it for streaming.** The shared 60s client would kill a long streamed script mid-sentence while tokens were still arriving. Copy the client, set `Timeout: 0`, rely on `ctx`. Pin it with a test: a server that streams for longer than a deliberately tiny client timeout must still deliver the full text.

**Share the credit formula between `Generate` and `GenerateStream`.** Separate copies let the same work be billed differently depending on whether the user watched it arrive.

**Workspace-scoped analytics loops (nightly aggregate → systemprompts metadata → holdout for lift) — see `references/workspace-insights-loop.md`.** Load before building any feature of the form “learn from past outcomes per workspace, inject the top signals into future vendor prompts, measure lift”. Covers the four-piece shape (canonical table + store CRUD + scheduler job + systemprompts hook), z-score + shrinkage math, degraded-flag thresholds for thin samples, deterministic hash-based holdout, and the pitfalls (global feature-join scoped client-side, empty-value tuple guard, hook-text normalisation, duration bucketing).

**Cross-process SSE: use Postgres `LISTEN`/`NOTIFY`, not Redis pubsub.** Background binaries (`apps/scheduler`, `apps/worker-core`) cannot share the API's in-memory `services/events.Bus`, so a job that updates data a UI tab is watching (publication metrics poll, render progress persisted from the worker, future analytics backfills) has to deliver its event cross-process. The repo already holds a Postgres pool in every binary and the API already holds an idle connection it can dedicate to listening — issue `pg_notify('openstudio_events', json_build_object('event', 'publication.metrics.updated', 'data', ...))` from the writer, open ONE dedicated `pgx` connection in the API at startup, `LISTEN openstudio_events`, decode in a loop, and re-emit into the local `events.Bus` that SSE handlers already subscribe to. The listener owns its own connection (not borrowed from the pool) and reconnects with backoff on error — Postgres closes idle NOTIFY listeners after some backend timeouts. Payload stays under 8 KB (Postgres' NOTIFY limit) by shipping ids plus event type only; the SSE handler reloads the row from the DB. Do NOT introduce Redis pubsub for this seam — the Postgres channel is already there and avoids a second dependency the stack otherwise doesn't need.

**Streaming is discovered by type assertion in `live_scripts_stream.go`**, so a new streaming adapter needs no handler change — but verify the assertion holds (`var _ aigw.TextGenStreamer = (*Provider)(nil)`), or streaming silently degrades to the spinner path with no compile error.

## Build & test pitfalls

- `go build ./services/...` fails ("directory prefix services does not contain modules listed in go.work") — `services/*` are separate modules; build/test per module (`cd services/pricing && go test ./...`). Root `go test ./...` tests NOTHING. Grep output for `^FAIL`.
- **Keep `git commit` / `git push` in their own terminal call, after the verification call has returned.** A long `tidy && build && test && commit && push` chain can trip the approval gate on the mutating tail; the gate times out, nothing in the chain runs, and the build/test evidence is lost with it. Verify first (read-only), read the exit codes, then commit, then push — three calls.
- **Never chain `&& echo OK` after a piped build or test command — the pipe's exit status is the LAST stage's, so the success marker prints over a real failure.** `go build ./... 2>&1 | head -4 && echo BUILD_OK` prints the compiler error AND `BUILD_OK`, because `head` succeeded; skimming for the marker then reports a broken build as green. Run the command bare and read its own exit code, or put the verification in a separate call. Same trap with `| tail`, `| grep`, and any `set -o pipefail`-less shell.
- **Anchor binary-artifact `.gitignore` patterns** (`/api`, not `api`): a bare name matches any path component, so new files under `apps/api/` are silently skipped by `git add -A`. Confirm with `git check-ignore -v <path>` (exit 1 = not ignored) before committing a new file in a Go app dir.
- **Duplicated pipelines drift silently — probe for divergence BEFORE refactoring, and turn each divergence into a named regression test.** `apps/api/live_tts.go` and `apps/worker-core/activities/tts.go` each owned the same TTS pipeline and had already drifted in two measurable ways: the worker truncated the sha256 cache key to 32 chars while the API used 64 (so the render path never reused audio the API had paid for), and the API wrote/read `duration-ms` while object stores canonicalise user metadata to Title-Case (so every API cache hit read duration 0 and shipped silent audio with no caption timings). Both were found by writing throwaway probes that printed the two implementations' outputs side by side. Metadata lookups should be case-INSENSITIVE so objects already written under either convention keep resolving. The same shape bites inside ONE package when sibling POST/GET handlers each independently derive a cache/dedup key — e.g. POST computes `lastMessageID` from `ListMessages(..., limit=40)` picking `msgs[n-1]`, GET uses `limit=1` picking `msgs[0]`; empty-state tests pass vacuously because both resolve to `""`, and the drift only surfaces once there is real multi-row history. Factor the key derivation into a shared helper, and seed the regression test with enough rows that the two selections diverge if the logic does.
- **When two modules must agree, have each assert against the SHARED package — never import one app module from another for a test.** An early draft had `apps/api` depend on `apps/worker-core` just to compare keys, inverting the dependency for a test's sake (and `go.mod` cannot express test-only). Each side comparing to `tts.AudioKey` gives the same guarantee transitively.
- **A missing test dependency makes a whole feature's tests skip — and a skip prints as PASS.** The shared `/live` test state had no media client, so all 11 external-audio tests skipped while the package summary read `ok`. Wire the real client when the service is reachable, and when a feature's tests pass suspiciously fast, re-run with `-v` and confirm they RUN.
- **Generate real media in tests rather than using byte fixtures when the claim is about measurement.** The concat-drift and probe-vs-sum findings are invisible with fake bytes; `ffmpeg -f lavfi -i sine=frequency=440:duration=N` produces a real MP3 in milliseconds. Supply deliberately WRONG per-segment durations so a summing implementation fails loudly.
- **A `t.Skipf` prints as PASS on the package summary line — a suite can be entirely green while asserting nothing.** Two harness bugs produced exactly that: `ids.New(prefix)[:8]` is a near-constant prefix, so every `INSERT INTO platform.workspaces` collided on the primary key, every subtest hit `t.Skipf("cannot seed workspace")`, and four tests reported PASS having run zero assertions (use the full id). Separately, a `t.Cleanup` closure capturing `st.db` panics when a subtest sets `st.db = nil` to exercise the no-database path — bind the store to a local before registering the cleanup. When a DB-backed test passes suspiciously fast, re-run with `-v` and confirm the subtests actually RUN rather than skip.
- **A round-trip test cannot pin a READER's defence against a field its WRITER never emits.** The rule under test was "resume must never restore the audio-review gate flag" — the test wrote state, read it back, and asserted the flag was false. It passed with the reader deliberately mutated to trust stored input, because the serialiser omits that field entirely, so there was nothing to restore. Any "we refuse to honour X from storage" guard must be fed a hand-built payload that explicitly CONTAINS X (a hand-edited blob, or one written by a future version that does persist it); a writer→reader round trip only ever proves the writer. Keep both tests: the round trip for the writer, the hostile payload for the reader.
- **A "rejects X" test that uses a NONEXISTENT resource proves nothing.** Removing the cross-tenant audio-key check left the rejection test passing, because a missing key 404s anyway — the check was load-bearing and untested. Put a REAL, fully valid object under the other tenant's prefix, then assert the rejection. Same trap for any negative test: make the thing exist, so only the guard can be what stops it.
- **Structural invariants need structural tests.** "There is exactly one render path" and "this constant lives in one package" cannot be observed behaviourally. Walk the source with a regex, skipping comments (the lesson is often written in them) and exempting the package that legitimately owns the pattern — see `apps/api/render_path_test.go`. Verify by dropping a deliberate violation file into the package and watching each test fail with its own message; a structural test is the easiest kind to write vacuously.
- **Check whether the compiler already forbids the violation you are testing.** The first render-dispatch probe referenced `RenderInlineActivity` from `apps/api` and simply did not compile — cross-module, so unreachable by construction. The realistic bypass was naming the activity by STRING, which compiles fine. Test the form that can actually happen.
- **Scope DB assertions to the row under test, not to the workspace.** `SELECT count(*) … WHERE workspace_id='ws_demo'` made an external-audio test fail whenever another test left a row behind. Count by content hash or id so the test is order-independent.
- **Mutation-test every guard, and when a mutant survives, document it rather than deleting the test.** Reintroduce each bug and confirm the specific test fails with the message you expect. One surviving mutant was informative: removing the app-level double-settle guard moved no balance, because `ledger.MemStore.Settle/Release` are already idempotent (`Status != "held"` → no-op). The guard was kept for its distinct job — logging a double resolution as an error instead of letting a buggy `defer` chain be absorbed silently — and that logging got its own test, which *does* fail when the guard is removed. Capture logs with `slog.SetDefault(slog.New(slog.NewJSONHandler(&buf, …)))` restored via `t.Cleanup`, and assert both that the raw cause IS in the logs and that it is NOT in the response body.
- **A fake provider still has to supply provenance.** `FakeDecision` set `Degraded: true` correctly but left `VendorID` empty, making its own score unstorable because `content.quality_scores` rejects a row with no vendor attribution. The rejection was right; the fake was wrong — fakes carry an honest id (`fake:decision`). Any fake feeding a table with a NOT-NULL provenance column needs the same.
- **Tests that run only against a fake provider cannot demonstrate model behaviour.** The fake decision provider returns one invented distribution, so guard tests built on it pass whether the model works or not. Keep a parallel `//go:build onnx` test exercising the real embedder through the same chain, skipping loudly (never vacuously) when it is unavailable — see `apps/api/stage_guard_laya_test.go`, whose benign cases are exactly the topics argmax false-flagged during calibration, so it doubles as a regression test for thresholding over argmax.
- `packages/schemas` and `packages/compositions` use `tsc --noEmit` as typecheck; not every package has a `pnpm typecheck` script — read `package.json` first.
- The `patch` tool with an `old_string` that spans a function boundary can splice two functions together when the closing brace + next `func` line isn't unique. When editing a map literal near a function's `}` + `func kindTagline(...)`, include a unique anchor from only ONE side.
- **`apps/web` vitest needs `NODE_ENV=test` on the invocation, not just in vitest.config.** The repo `.env` sets `NODE_ENV=development` and godotenv/dotenv leaks it into the test process; React then loads its production bundle, `act()` is missing, and Testing Library warnings become hard failures. Fix in `package.json`: `"test": "NODE_ENV=test vitest run"`. Also `define: { 'process.env.NODE_ENV': '"test"' }` in vitest.config as belt-and-braces.
- **happy-dom cannot host Radix UI primitives that use PointerCapture APIs.** `@radix-ui/react-select`, `dropdown-menu`, and `tooltip` throw `setPointerCapture is not a function` under happy-dom (and partially under jsdom). In test files, module-mock the affected component with a native replacement: `vi.mock("@/components/ui/select", () => ({ Select: ..., SelectItem: ..., ... }))` returning a plain `<select>` wrapper. Tests for the underlying business logic still run; the exact Radix rendering isn't what's under test.

## Subagent dispatch for OpenStudio work

**Before dispatching a subagent against a plan, verify the plan's cited paths exist on the base branch.** Multi-task plans ship with "Verified ground truth" sections citing `apps/api/stage_video.go:320`, named functions, line ranges. A plan written against one branch and executed against another cites files that do not exist — subagents against stale paths guess wildly or fail opaquely. Spend 60 seconds: `ls` every cited path, `wc -l` where line numbers are given, grep for a named function. If anything misses, STOP and clarify the base branch; the plan may expect a merge that has not happened. Common failure shape: plan says 'branch off main' but every refactor target only exists on an unmerged feature branch — merge the feature branch first (or confirm the user wants to base off it) rather than building from scratch.

Wide multi-milestone tasks ("add capability + adapter + activity + composition + kind + docs + commit") routinely hit the 50-call subagent cap. Structure the goal so the subagent COMMITS AND PUSHES the moment tests pass, before doing docs/env updates — otherwise the cap hits with uncommitted work and the parent must reconstruct state from the transcript. Split wide fan-out into two subagents (gateway + adapters | compositions + kind wiring) rather than one giant task.

`delegate_task` rejects goals containing an unexpanded `{name}` placeholder. This trips on prose referencing API paths like `/history/{prompt_id}` or `/renders/{id}`. Rewrite as "the prompt id path segment" or use ALL-CAPS (`/history/PROMPTID`) — never leave literal curly braces in the goal string.

**Parallel dispatch cap is 3 subagents per `delegate_task` call.** More is refused with `Too many tasks: N provided, but max_concurrent_children is 3`. When the plan has 4+ disjoint tracks, dispatch three now and queue the fourth for when a slot opens (a returned subagent frees a slot). Do NOT chain a fourth task into one of the three's context — that inflates their scope and pushes them into the iteration cap.

**When a subagent hits the iteration cap with REAL work on disk but uncommitted, the parent commits that work directly — do not dispatch a continuation child.** A continuation re-reads the whole diff to orient and burns most of its budget before writing a line; the parent already has every path on disk from the subagent's transcript. Verify the uncommitted work in the parent (`git status --short`, `go build`/`go test`/`pnpm test`), then `git add` the EXPLICIT file list (never `-A` — the subagent likely left generated files like `apps/web/next-env.d.ts` or `go.sum` churn alongside the real deliverables) and commit with the subagent's own commit message if its summary wrote one. Dispatching a continuation here is paying a child's full iteration budget to do what `git commit` does in one call.

**When the same track hits the iteration cap twice, the parent finishes the remainder itself.** A second "continuation" child re-reads the whole diff to orient and burns most of its budget before writing; a third would do the same. Once the leftover is a list of small, well-specified items (a scheduler job, an ADR section, a go.mod line, deleting a stale test case), do them directly — verify first with `go build`/`go test` per module, because the child's "does not compile" usually means one stale test file, not the main package. Write every continuation brief as an explicit file-state ledger: committed shas, uncommitted files by path with what each contains, and the numbered items still open — never "finish the API side".

**Subagent self-reports go stale between the last tool call and the summary write.** A subagent that hit the iteration cap while iterating on tests may report "3/5 passing" when a subsequent run — with fixes already on disk — would show 5/5. Before dispatching a finisher based on a "partial complete" summary, re-run the actual verification (`go test`, `pnpm test`, `git log`, `curl` the endpoint) yourself. Half the time the parent finisher is unnecessary or scoped too wide. Dead giveaway: subagent describes a fix as "needed" but the diff it applied already contains that fix.

**Subagents that commit sweep up every untracked file unless you scope the add.** `git add -A` / `git commit -am` / `git commit -A` stage stray docs, `.claude/`, built binaries like `apps/cli/cli`, `skills-lock.json` — the commit scrolls past in the summary and lands on main. Mitigate: specify the exact file list in the task context ('Stage ONLY `main.go`, the test file, `testdata/*`. Do NOT `git add -A`.'), AND verify after handoff with `git show --stat HEAD`. On drift: `git reset --soft HEAD~1 && git restore --staged <stray> && git commit -c ORIG_HEAD --no-edit`. Dropping stray files locally beats cleaning them from main after merge. Same bug on the parent side when sibling children leave untracked edits.

**Sibling subagents dirtying the working tree block rebases.** With three subagents pushing to the same branch, one commonly has an in-flight edit (e.g. lockfile change, generated schema file) that makes the other's `git pull --rebase` refuse. Pattern the parallel goal to include: `git stash push -m sibling-wip -- <file/glob>` around the rebase, then `git stash pop`. Or restrict each subagent's file scope tightly enough that no overlap exists. On this repo, common contended files: `pnpm-lock.yaml`, `apps/web/next-env.d.ts` (Next.js auto-regenerates), `packages/schemas/src/index.ts` (multi-track shared entrypoint).

**Dispatch backend subagent + build UI concurrently when the API contract is clear.** The split that has worked for a vertical slice with a vendor leg is THREE children: (1) `services/ai-gateway` only (capability shape + adapters + fakes, httptest), (2) `apps/api` + `services/db` + `apps/scheduler` + ADR, (3) `apps/web` only — with the JSON/multipart contract written verbatim into all three briefs and "code to the contract, do not wait for the sibling" in (2) and (3). Child (2) may need a field the gateway child is adding; tell it to add the minimal shim itself and say so, rather than block. Give every child an exact `git add <paths>` list and "do NOT stage apps/web / docs/prd / go.work.sum" — the user keeps untracked planning docs in the tree, and sibling edits sit uncommitted beside yours. For vertical slices with a defined multipart/JSON contract (custom presenter CRUD, new admin endpoint, etc.), dispatch the backend as a subagent and START the UI in the parent immediately — do not wait for the backend to land. The subagent's write scope is `services/db/store/`, `apps/api/*.go`, migrations. The parent's write scope is `apps/web/`. No overlap, no rebase collisions. When both finish, the parent merges the subagent's commit onto the same branch (or cherry-picks). BUT: if the subagent starts mid-flight modifying a shared Go file the parent also has staged (e.g. both editing `services/db/store/characters.go`), `git commit -a` in the parent will grab the subagent's uncommitted changes. Guard with `git reset HEAD <file>` before the parent's commit, or scope the parent's `git add` to `apps/web/` explicitly. Also: subagents inherit whatever branch is currently checked out, so `git branch --show-current` in the parent before dispatch determines which branch the child commits land on — verify this matches the subagent's intended branch name in its task description, or accept that the parent will need to rescue the commit onto the right branch (see next paragraph).

**Subagent commits can land on the wrong branch when parallel children share a working tree.** A subagent asked to commit to branch A sometimes commits onto branch B if a sibling checked B out first — the subagent's `git commit` records against whatever HEAD points at, not against its task's intended branch. Rescue without losing work: `git stash push -u -m 'parent wip'` first (parent's working tree survives the juggling), then `git checkout <intended-branch>` and `git cherry-pick <sha>` from where it wrongly landed, `git push`, then `git checkout <wrong-branch>` and restore it with **`git reset --keep origin/<wrong-branch>`** — Hermes refuses `git reset --hard` as destructive but accepts `--keep`, which is also safer (aborts if any file has both index and worktree changes). Finish with `git stash pop`. Symptom that this is what happened: `git branch -vv` shows the intended branch still at its old head while the wrong branch is ahead by one commit that the subagent's report described as landing on the intended branch.

## Merging feat/* → main

Long-lived feature branches on `apps/web` accumulate untracked churn in Next.js auto-generated files. `apps/web/next-env.d.ts` regenerates on `pnpm dev` or `pnpm build` and shows as `M` on `git status` even when nothing was intentionally changed. `git checkout main` refuses the fast-forward with `error: Your local changes to the following files would be overwritten by merge: apps/web/next-env.d.ts`. Fix: `git checkout apps/web/next-env.d.ts` (discard the auto-regen), then retry `git merge --ff-only <branch>`. Same trap on any Next.js repo — solve it once as part of the merge routine, not each time the merge fails.

Private repos on GitHub Free-tier cannot inspect branch protection via API (`repos/{owner}/{repo}/branches/main/protection` returns 403 `Upgrade to GitHub Pro`). This is not a permissions problem with the CLI — it's a plan restriction. Assume no branch protection on Free-tier private repos and merge directly rather than trying to detect required checks first.

## AI provider resolution (services/ai-gateway/factory)

Each capability follows `cloud (if API key set) → local (if server reachable) → fake` and logs the choice at startup as `aigw: <Cap>=<source>`. When adding a new capability, mirror the existing pattern in `factory.go` — do not invent a new resolution order. Locals: `localtextgen/` (llama.cpp OpenAI-compat, Mistral-24B), `localvision/` (llama.cpp multimodal, Qwen2-VL), `laya/` (onnxruntime-go embeddings), `wan21comfy/` (ComfyUI HTTP for video). TTS has NO local adapter — only cloud (OpenAI/ElevenLabs) or fake. ASR has `services/ai-gateway/localwhisper/` shelling out to `whisper-cli` (brew: `whisper-cpp`) with `~/.cache/openstudio/models/ggml-base.en.bin` — pair with `PROVIDER_ASR=local|cloud|fake` to pin it. Verify the chosen providers in `/tmp/os-logs/api.log` on boot.

**`NewAuto()` must be called at startup — the API had it wrong twice.** If `/tmp/os-logs/api.log` shows no `aigw:` lines after boot, the factory was never invoked and every capability is silently fake, no matter what keys are in `.env`. Common shape of the bug: `apps/api/main.go newState` initialises `s.aigw = &aigw.FakeTextGen{}` unconditionally, and the media-client branch also creates `gw := aigw.NewFake()` for the renderer — both must be replaced with `aigwfactory.NewAuto()` and its `TextGen` must overwrite the placeholder. `st.gateway` and `s.aigw` are SEPARATE fields; wiring one does not wire the other. Grep for every `aigw.NewFake()` and `&aigw.FakeTextGen{}` in `apps/api/*.go` before assuming providers are live.

**Registered capabilities are not consumed capabilities — the `aigw:` startup line only proves the KEY resolved, not that the pipeline uses it.** Adapters in `services/ai-gateway/*` (higgsfield for VideoGen, imagegen for ImageGen, laya for Decision, wan21comfy for local video, etc.) can appear as `aigw: VideoGen=cloud:higgsfield` at boot while zero handlers or Temporal activities ever call `.Generate()`. This is the difference between "a real provider is available" and "the pipeline produces real content from that provider". Before describing a capability as producing anything — in commit messages, user summaries, or 'what does this pipeline do' answers — grep the actual consumer sites:

```bash
rg -n '\.VideoGen\.Generate|\.ImageGen\.Generate|\.Decision\.' apps/api apps/worker-core/activities
```

Zero matches on a capability means it is UNUSED in the shipped path, regardless of the startup log. When the user asks which AI generates something, the honest answer is only the adapters actually invoked during a real render. The Remotion composition + real TTS + real ASR is a *templating engine with real audio*, not video generation — do not oversell it as the latter. Overselling here is the fastest way to burn user trust; when they open the rendered MP4 and every topic looks the same behind the presenter, the mismatch between the description and what was shipped becomes the whole conversation. See `references/motion-graphics-composition.md` for the B-roll wire-up pattern that turns an unused VideoGen adapter into an actual per-scene visual consumer.

**Laya (`Decision`) silently fabricates confident scores when its ONNX model is absent — never persist or display a score without checking provenance.** `services/ai-gateway/laya` is all-MiniLM-L6-v2: `Decide()` embeds the text and cosine-matches it against the label *description strings* in `registry.go` (`moderation-prefilter`, `script-quality`, `topic-classify`). When the model file or the onnxruntime shared library is missing, it does NOT error — it falls through to `hashDistribution(text, labels)`, a SHA-256-derived distribution that looks exactly like a real result. The only tell is `Usage.Cost.VendorID`: `local:laya-minilm` is real, `local:laya-fallback` is hash noise. Any feature that stores or surfaces a quality/safety score must read that VendorID, persist it alongside the score with a `degraded` boolean, and refuse to display or gate on a degraded score. Baking in "a score on every stage output" without this check means every asset on a machine without the model carries a scientific-looking number that is a hash of its own text.

**`ModelAvailable()` is not a readiness check — use `EmbedderReady()`.** The former only stats the model file, so it returns true on a machine where the embedder cannot load, which is exactly how `factory.go` logged `Decision=local:laya-minilm` while every score was hash noise. Three independent things must all hold or Laya degrades silently: (1) `github.com/yalue/onnxruntime_go` present in `services/ai-gateway/go.mod` — it was absent for the model's entire existence, so the real embedder had never compiled; (2) `ONNXRUNTIME_LIB` pointing at `libonnxruntime.{dylib,so}` (the Go binding dlopens that exact path, it does not search); (3) the binary built with `-tags onnx` AND `CGO_ENABLED=1`. Boot verification is one grep: `laya: embedder=ready` vs `laya: embedder=DEGRADED`. Full setup incl. cloud/Docker in `docs/laya-setup.md`.

**Laya calibration and limits — see `references/laya-classifier.md`.** Load it before changing registry phrases, the softmax temperature or the `ReadVerdict` threshold, or before asking Laya to score anything new. Never gate on argmax, and never treat a clean Laya score as real moderation of user-facing output.

**Fake-mode content is developer output, not user content.** Every capability handler that surfaces model output to users must sanitise: check for the `[fake:` marker AND for prompt-fragment echoes (specific phrases from the prompt template like `Return in two parts`, `A markdown script (headings`, `<SCENES>` block markers) and either substitute a plausible fallback keyed off the user's inputs or return an explicit error. Each fake provider has its OWN marker — audit them per capability: `FakeTextGen` prefixes output with `[fake:textgen h=<hash>]`; `FakeASR` returns exactly `[{Word:"fake"...}, {Word:"transcript"...}]` regardless of input (detect by `len==2 && [0]=="fake" && [1]=="transcript"` and synthesise word timings from turn text distributed evenly over durationMs); `FakeTTS` returns placeholder bytes that ffprobe reads as 0-second audio. Match on the marker, not the presence of `AI_PROVIDER_MODE=fake` — real providers occasionally echo prompts too. Sanitisation belongs on the API-side response path, not the frontend — the frontend cannot distinguish a real short script from an echoed prompt. Also strip fake output from log lines you might surface (e.g. progress messages, quotes). **The echo heuristic must require multiple specific-phrase hits, not single common tokens** — matching a single word like `write a` fires on legitimate LLM output that uses imperative phrasing ("Write a note to yourself...") and then wraps the real narration into a synthesised fallback. Require ≥2 distinct prompt-template phrases before treating output as an echo.

**Seed variants keyed by feature id, not array index.** When a seed groups templates/presenters/voices by a parent bucket AND applies per-item variants (`titleVariants[]`, transition sets, etc.), keying the per-item value by iteration index (`titleVariants[tplIdx++]`) silently misaligns everything the moment the seed order or group count changes. In the wild: a `titleVariants := []string{"kinetic", "slab", "sticker", "neon", "kinetic", "slab", "sticker", "neon"}` array iterated with `tplIdx++` across 4 groups × 2 templates gave `tpl_mg_dark_1` a `"sticker"` variant instead of the intended `"slab"` — visible only when a downstream consumer (composition, wizard) branches on that variant field. Key by the group id instead:

```go
titleVariantsByGroup := map[string]string{
    "light-clean": "kinetic",
    "dark":        "slab",
    "playful":     "sticker",
    "loud-bold":   "neon",
}
// ... inside the loop:
TitleCardVariant: titleVariantsByGroup[g.id],
```

This breaks in a way `go test` cannot catch: the seed runs successfully, the row exists, downstream reads return a real value — it's just the WRONG value. Verify via the API path the UI reads (`curl /api/v1/motion-graphics/templates | python3 -c 'for t: print(t["id"], t["titleCardVariant"])'`) before assuming a Look's chrome is broken elsewhere. Same rule applies to any "one per group, family of items" seed pattern — presenter nameplate colours, voice tier assignments, etc.

**Reseeding a table with FK-dependent children needs the child FK nulled first.** A migration that wipes a catalog table (`DELETE FROM content.templates`) blocks with `violates foreign key constraint "scripts_template_id_fkey"` when any child row has recorded a reference to the doomed parent. Fix in the migration itself, in this order:

```sql
UPDATE content.scripts SET template_id = NULL WHERE template_id IS NOT NULL;
DELETE FROM content.templates       WHERE deleted_at IS NULL;
DELETE FROM content.template_groups  WHERE deleted_at IS NULL;
```

Do NOT `ON DELETE CASCADE` the child column just to make the migration go through — that hides genuine referential integrity in production. The null-out only applies to the reseed pattern where the child reference is soft (a metadata link, not a required composition). Same trap on any catalog wipe: `content.characters` seeded rows referenced from `content.projects.presenter_ids[]`, `content.voices` referenced from character bundles, etc. Grep for `REFERENCES content.<table>` before writing a wipe migration and null-out every soft child in the same statement block.

**LLM adapter default models must use aliases or current dated versions, not stale fingerprints.** Anthropic/OpenAI deprecate dated model strings roughly quarterly and return 404 with a `not_found_error`. The default in each adapter (`services/ai-gateway/anthropictext`, `services/ai-gateway/openaitts`, etc.) should be a documented alias (`claude-sonnet-4-5`, `gpt-4o-mini-tts`) or the current dated version. When a `/live/*` endpoint returns 500 with the sanitised "try again" message, check `/tmp/os-logs/api.log` for the raw provider error — a `not_found_error` about a model id means bump the default in the adapter.

**Real LLM output carries markdown scaffolding TTS will speak aloud.** This is a DIFFERENT bug from prompt echo: even correct, high-quality real LLM output emits `## Section`, `**bold**`, `---` horizontal rules, code fences, list bullets, and label prefixes like `Narration:`, `Script:`, `Part 1:`, `Scene 3:`. Feeding that straight into a TTS provider makes it read "hashtag hashtag hook" and "asterisk asterisk bold asterisk asterisk" verbatim. The strip-and-split pipeline (`services/scripts.NormalizeMG` + `CleanForDisplay`) MUST run between the LLM response and both (a) the wizard textarea shown to the user and (b) any TTS synthesis — not one or the other. When adding a new content-generating capability, mirror the sanitisation call sequence from `apps/api/live_scripts.go`: `parseScriptOutput` → `scripts.CleanForDisplay(text)` → `scripts.NormalizeMG(clean, mode)`. Skip either step and structural markers leak through to the user or into the audio.

**Local sub-7B LLMs echo XML-tag prompt scaffolding back verbatim — write the prompt with prose section labels, not `<design>...</design>` style tags.** Wrapping prompt sections in XML-like tags (`<design>...</design>`, `<script>...</script>`, `<constraints>...</constraints>`) is a natural instinct — Claude and GPT-4-class models handle it well. Qwen2.5-3B and similar sub-7B models parse the tags as literal template output and dump the entire scaffold (including nested `<audio>` / `<constraints>` blocks) into their response body instead of writing the requested content. Use plain labelled sections instead: `Design & pacing (match this in the writing — do NOT describe it):\n<directive>\n\nOne narrator. Write flowing narration...\n\nReturn in two parts: ...`. The prose form gives the model the same structure without a tag pattern it can mistake for expected output. Same lesson applies to any structured-input prompt to a small local model — treat XML-like tags as write-once, cloud-only sugar. When the model is unclear (mixed local + cloud deployments), default to prose labels — cloud models tolerate both, only local models fail on tags.

**Local sub-7B LLMs skip structured-output instructions however the prompt is worded, and need a strict → prose → scenes-to-body → topic-only fallback parser chain — see `references/stage1-script-generation.md`.**

**Voice IDs are provider-specific; our seed IDs are aliases, not passthroughs.** The wizard shows stable OpenStudio ids (`voice_seed_narrator`, `voice_seed_female_std`) but ElevenLabs/OpenAI expect their own ids (20 alphanumeric chars for ElevenLabs). The adapter is the right place to translate — see `resolveVoiceID` in `services/ai-gateway/elevenlabstts/elevenlabstts.go`. The precedence that actually works for Free-tier ElevenLabs accounts: (1) real 20-char provider id passes through; (2) `ELEVENLABS_DEFAULT_VOICE_ID` env override wins over the alias table so operators can pin their personal voice without touching code; (3) alias table falls back; (4) stock default last. `ELEVENLABS_DEFAULT_VOICE_ID` must come BEFORE the alias lookup — putting the alias table first sends known seed ids to library voices and Free tier rejects them.

**ElevenLabs Free tier: `category=premade` voices are blocked via API even with a valid key.** The 402 error is `paid_plan_required` with `Free users cannot use library voices via the API`. This is not a key/scope problem; the account tier permanently blocks stock voices (Rachel, Bella, Josh, etc.) for API calls regardless of key permissions. `GET /v1/voices` on a Free account returns ~20 voices ALL with `category: premade` — none of them are API-usable. The user must **generate a custom voice** in the ElevenLabs dashboard (Voice Design → describe/prompt); generated voices carry `category: generated` and are Free-tier API-callable. Alternative: upgrade to Starter tier (unlocks premade over API). "Default voices" appearing in the dashboard's My Voices tab are still `category: premade` — dashboard placement isn't the signal, `category` is.

**When debugging ElevenLabs voice access, the API key needs `voices_read` scope.** Keys scoped only to `text_to_speech` succeed at synthesis but return `missing_permissions` on `GET /v1/voices`, blocking category-inspection probes. Ask the operator to regenerate the key with `voices_read` added; then a small probe (`GET /v1/voices` with header `xi-api-key`) enumerates ids + names + categories to pick a `generated` one for `ELEVENLABS_DEFAULT_VOICE_ID`.

**Temporal helpers panic outside a real activity context — wrap them for unit tests.** `activity.GetLogger(ctx)` and `activity.RecordHeartbeat(ctx, ...)` (and any other `activity.*` helper that reads the outbound interceptor) panic with `getActivityOutboundInterceptor: Not an activity context` when called from a plain `context.Background()` in `go test`. This makes activity unit tests unusable unless every helper is guarded. Ship a `heartbeatSafe(ctx, details...)` + `getActivityLogger(ctx)` pair in the same file as the activity, using `defer recover()` and falling back to `slog.Default()` wrapped in a `log.Logger` adapter:

```go
func heartbeatSafe(ctx context.Context, details ...any) {
    defer func() { _ = recover() }()
    activity.RecordHeartbeat(ctx, details...)
}

func getActivityLogger(ctx context.Context) log.Logger {
    defer func() { _ = recover() }()
    // returned logger doubles as slog fallback via a small adapter
    return activity.GetLogger(ctx)
}
```

Without the wrappers, `TestHiggsfieldGenerate_SuccessUploadsAndPolls` (and every other activity test) fails immediately with the interceptor panic and the actual behaviour under test never runs. Do this at activity-file creation time, not after the first failing test — activities without helpers are activities without tests.

**`workflow.GetVersion(ctx, "change-id", floor, max)` floor is the oldest VERSION MARKER Temporal must still accept, not the oldest branch body left in the code.** Deleting the DefaultVersion branch body does NOT justify pinning floor to `1` — histories recorded before the change-id existed carry `version=-1` (DefaultVersion), and a floor of 1 rejects them at replay with `TMPRL1100: Workflow code removed support of version -1`. If the surviving v=1 path produces behaviour identical for both markers (common when all you did was collapse branches), keep `workflow.DefaultVersion` in the floor so pre-change-id histories still replay. Only raise the floor when every in-flight pre-change-id workflow has drained. Pin with a replay test against a REAL captured history (`temporal workflow show --workflow-id <id> --output json > testdata/<name>.json` then `worker.NewWorkflowReplayer().ReplayWorkflowHistoryFromJSONFile`) — do NOT hand-forge `historypb.History` JSON, event ids/task tokens/`EventTime`/batched command attributes make guesses incorrect. If no stack can produce a fixture, stop and say so; a `t.Skip` on a replay guard looks green while asserting nothing.

**Temporal activities that call external providers MUST declare a bounded RetryPolicy — default is unlimited.** Without explicit `RetryPolicy{MaximumAttempts: N}` on `workflow.ActivityOptions`, a Temporal activity retries forever with exponential backoff. On a 402/404 (permanent provider error), that means every render-in-progress hammers the provider endpoint until an operator manually terminates the workflow — burning API quota, filling logs, and stuck-render UX. Every activity that hits an external HTTP API (TTS, ASR, image-gen, video-gen) needs `RetryPolicy: &temporal.RetryPolicy{InitialInterval: 2*time.Second, BackoffCoefficient: 2.0, MaximumInterval: 30*time.Second, MaximumAttempts: 3}` on the `ActivityOptions` passed to `workflow.WithActivityOptions`. In-process pure-compute activities can inherit defaults.

**Failure of the thing-the-user-asked-for is TERMINAL — do not silently fall back to a different product.** The gate is "is this the point of the render for THIS kind?", not "is this field optional in the schema?". Motion-graphics visuals ARE the motion-graphics product; shipping presenter+captions+audio when visuals fail is a different product delivered under the motion-graphics label — audio still played and captions still displayed, but every frame drew the template background, and the user opens the MP4 to find a black video. For `motion-graphics` and any kind whose defining feature is a generated visual, the workflow aborts terminally (`return nil, err`) on both `brollErr != nil` AND `Result.Degraded == true` (partial-success is terminal too — one missing scene is a defect, not a degradation). The error carries through Temporal to the API; the stage endpoint returns 5xx; the ledger's reservation sweeps on expiry. No in-band `Degraded=true` flag quietly ships a stripped-down render.

Genuinely-optional additions — a translation subtitle track on top of the baseline captions, a watermark variant, cover-art flourish on an audio-first product — may still degrade when they fail. The test for "optional": removing it entirely leaves a complete version of what the user asked for. If removing it produces a different product (presenter-only when they asked for motion-graphics), it is not optional, and failing it must be terminal. Pin the terminal behaviour with Temporal-testsuite tests for every kind whose defining visual is non-optional — a non-retryable visuals error AND a `Result.Degraded=true` both assert `env.GetWorkflowError() != nil` and the error message contains `scene visuals`.

**External-provider adapters MUST normalise vendor parameter formats at the adapter boundary — not push vendor error surfaces up to the workflow.** Every vendor accepts a slightly different flavour of the same request: aspect ratios as `9:16` vs `9x16` vs `vertical` vs `1080x1920`, durations in seconds vs milliseconds vs integer-only vs floats, model names as slugs vs versions vs aliases. OpenStudio uses one internal shorthand (aspect ratios as `9x16` throughout schemas, DB, and composition); each `services/ai-gateway/<vendor>/` adapter is where that shorthand becomes the vendor's actual accepted enum. Ship a private `normalizeAspectRatio(a string) string` (or similar) in the adapter and call it inside `Generate` before building the request body:

```go
func normalizeAspectRatio(a string) string {
    switch a {
    case "9x16":  return "9:16"
    case "16x9":  return "16:9"
    case "1x1":   return "1:1"
    case "4x5":   return "3:4"  // nearest match — vendor has no 4:5
    // ...
    }
    return a  // pass-through if already vendor-format
}
```

Same pattern for duration clamps: when a vendor rejects `duration < 4` (Higgsfield seedance-2.0 does), clamp in the WORKFLOW dispatch, not in the adapter — the workflow has the storyboard context to decide whether clamping is safe. Verify at the adapter-unit-test layer by asserting the outbound request body shape; `go test` at the workflow layer misses it. Full Higgsfield case + rejection symptoms live in `references/motion-graphics-composition.md`.

**Killing a stuck render is a two-step operation.** `POST /api/v1/renders/{id}/cancel` marks the DB record but Temporal keeps executing already-scheduled retry attempts for the current activity backoff window. To actually stop the traffic: (1) POST the cancel endpoint, (2) `pkill -f 'worker-core'` so in-flight activity workers exit, (3) restart the worker with the fixed code. Without step 2 you keep seeing `Activity error ... Attempt N` lines in the log for another minute or two after the cancel.

**Provider-mode override for local dev.** `PROVIDER_TEXTGEN=local|cloud|fake` in `.env` beats auto-resolution in `factory.NewAuto` — useful when a cloud key is present but out of credit and you want to force llama.cpp. The pattern is per-capability; mirror it (`PROVIDER_TTS=local|...`, `PROVIDER_MODERATION=...`) when adding new capabilities so operators can pin a slot without deleting keys. The factory logs `aigw: TextGen=local:llamacpp` regardless, so operators can confirm the override took.

**Running TextGen on local llama.cpp (fast Qwen bootstrap, the three timeouts that must tune together, `--parallel N` starvation) — see `references/local-llm-ops.md`.** Load it when switching to `PROVIDER_TEXTGEN=local`, debugging a `TEXTGEN_FAILED` on a local boot, or running batch scripts against the local server.

**Renderer owns captions, not the client.** Captions must be baked into pixels by the Remotion composition (rendered per-frame via `useCurrentFrame` inside the `<Captions>` primitive), not overlaid at playback by the video-viewer UI. This lets the MP4 be shared directly to any social platform and picked up by their built-in caption OCR without a separate captions track. Pass the theme's `palette.accent`/`palette.fg`/`fonts.body` through as `activeColor`/`inactiveColor`/`fontFamily` so styling comes from the template, not composition defaults. Any "toggle captions" UI on the render viewer would be a design mistake — the pixels are already committed.

**Data-hydration loops must never `continue` silently on missing prerequisites.** When enriching a payload in stages (TTS → duration probe → whisper → word timings), a guard like `if turn.DurationMs <= 0 { continue }` inside the whisper/timings loop silently ships an empty `wordTimings` array to the renderer when upstream (e.g. ElevenLabs) returned `DurationMs: 0`. The bug hides because the outer loop logs "success" and the renderer just draws nothing. Every guard-clause in a hydration pipeline must either: (a) fall through to a synthesised value keyed off available data (`total = wordCount * 180ms` when duration is zero), (b) log a WARN with the specific field and turn index that skipped, or (c) surface a hard error that halts the render.

The same failure wears a second costume in Go HTTP handlers: **`if v, err := f(ctx, ...); err == nil { ... }` is an error-swallowing idiom** — when `f` fails, the block is skipped and the zero value ships as a successful 200. A members list that errors becomes `[]`, which renders as a believable "no members yet" empty state rather than an error, so the bug survives a click-through review. Never bind an error you do not branch on: assign it, return `errs.Internal` (or the appropriate code) to the client, and `slog.Error` the raw cause server-side so the real message — a missing column, a permission denial — is recoverable from `/tmp/os-logs/api.log` without leaking it to the user. Treat a list endpoint that returns an empty array while the DB has rows as a swallowed error until proven otherwise. When debugging a "data present in log but missing on the wire" issue, `logger.Info("payload ready", "firstTurnDurationMs", ...)` at the point of dispatch and a matching debug log on the Node side gives a two-point diff — mismatch = hydration bug in the sender; match = deserialisation bug in the receiver.
